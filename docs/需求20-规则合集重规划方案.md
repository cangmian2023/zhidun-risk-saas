# 需求20 · 管理中心「规则合集」重规划设计（白话版方案）

> 说明：本方案只讲"改成什么样、哪个页面怎么改"，不堆代码/行号/文件名。落地实现等你拍板后动手。

---

## 0. 一句话目标

把现在的「规则合集」从"5 个分类页签 + 各自不同结构"重构成**一个统一规则列表 + 一个规则详情页**，并且对齐全站顶层框架：
- 页面功能 和 本地样例 JSON 数据 分离（数据继续落 `ruleHub.json`，橘标）；
- 页面显示**数据来源标签**（蓝=配置 / 橘=样例 / 灰=实时计算）；
- 规则的**状态**不再自己存一份，而是**读取所关联业务流程的配置状态**。

---

## 1. 顶层框架对齐（三件事必须先定）

| 框架要求 | 本页面怎么落地 |
|---|---|
| 功能 / 数据分离 | 列表和详情页只负责渲染；所有规则数据读本地样例 JSON，写回也只走该 JSON。页面里不写死任何规则。 |
| 显示数据来源标签 | 页面头部用全站统一外壳（自动带"蓝/橘/灰"图例）。规则本身标**橘（样例JSON）**；"关联业务流程状态"也标**橘**（它来自业务流程样例数据）；如果以后有实时算出来的命中率，再标**灰**。 |
| 规则状态读业务流程配置 | 每条规则增加一个"关联业务流程"字段。规则的有效状态 = 它所关联业务流程的审核状态（已上线→已生效；已下线→已下线；待初审/待复审→草稿待上线）。列表里的"状态"列直接读这个值，不单独维护。 |

---

## 2. 20.1 删除所有 tab，页面只保留一个列表

**改法（管理中心 - 规则合集页面）：**
- 删掉现在顶部的 5 个分类页签（核验规则集 / 反欺诈规则库 / 黑名单管理 / 团伙库管理 / 评分场景规则）。
- 页面主体变成**一张统一的规则列表**，所有类型的规则混在一起，靠"规则类型"这一列区分。
- 列表上方保留：页面标题、源标签图例、一个"＋ 新建规则"按钮、以及按类型/状态/风险等级的筛选条。
- 原来的右侧详情抽屉，升级成**独立的规则详情页**（见 20.3）。

## 3. 20.2 一个规则实例：属性与值（统一模型）

重规划后，所有规则共用**一套属性**（类型不同只是部分属性有值、部分留空）。下面给出一条完整示例，让你看清"属性 = 什么、值 = 什么样"：

| 属性（字段含义） | 示例值 | 说明 |
|---|---|---|
| 规则编号 | `R-2026-0001` | 全局唯一 |
| 规则名称 | 多头借贷强度监控 | 给人看的名字 |
| 规则类型 | 反欺诈 | **重要列**（见 20.4） |
| 风险等级 | 高 | 高 / 中 / 低 |
| 命中条件 | 近30天申贷平台≥7家 | 规则触发逻辑（大白话描述） |
| 处置动作 | 拒绝 / 转人工 | 命中后怎么办 |
| 权重 | 28% | 在规则集里的重要程度 |
| 适用范围 | 信用贷、经营贷 | 哪些产品/场景生效 |
| 负责人 | 风控策略-张 | 谁维护 |
| 更新时间 | 2026-07-18 | 最后改动时间 |
| 关联业务流程 | 贷中反欺诈审核流程 | 见 20.4 状态联动 |
| 有效状态 | 已生效 | **由上面关联流程的状态推导**，自己不存 |
| 类型专属·名单类型 | — | 黑名单类才有（手机号/设备/证件/银行卡） |
| 类型专属·名单值 | — | 黑名单类才有（如 `138****0001`） |
| 类型专属·模型名 | — | 设备风险/评分类才有（如"动态欺诈模型V3"） |
| 类型专属·命中分 | — | 设备风险类才有（如 0.87） |
| 类型专属·触发特征 | — | 设备风险类才有（如"模拟器特征+Root"） |
| 类型专属·机构×名单 | — | 跨机构名单类才有（如"机构A × 信贷黑名单"） |
| 说明 | 监测客户在多平台同时借贷 | 备注 |

> 一句话：用一个"大宽表"装所有规则，**通用属性人人都有，类型专属属性谁有谁填**。

## 4. 20.3 列表展示列 + 规则详情页设计

### 4.1 列表里挑哪些属性显示（重要列在前）

| 顺序 | 列名 | 来源属性 | 备注 |
|---|---|---|---|
| 1 | 规则名称 | name | 可点击进详情 |
| 2 | **规则类型** | ruleType | **重要列**，带颜色标签 |
| 3 | 风险等级 | riskLevel | 高=红 / 中=橙 / 低=绿 |
| 4 | 命中条件 | hitCond | 超长截断，详情看全文 |
| 5 | 权重 | weight | 百分比 |
| 6 | 关联业务流程 | flowRef | 显示流程名 + 其状态色 |
| 7 | 有效状态 | 推导自流程 | 已生效/已下线/草稿 |
| 8 | 更新时间 | updatedAt | 排序用 |

### 4.2 规则详情页（点列表任一行进入）

页面结构沿用全站详情页头部框架，自上而下分块：

1. **头部**：规则名称 + 规则类型彩色标签 + 有效状态标签（由流程推导）+ 风险等级。
2. **基本信息块**：编号、类型、适用范围、负责人、更新时间、关联业务流程（可跳去该流程配置页，并显示流程当前状态机：待初审→待复审→已上线→已下线）。
3. **规则逻辑块**：命中条件（全文）、处置动作、权重、风险等级。
4. **类型专属块**（按类型显示对应内容）：
   - 黑名单：名单类型 + 名单值 + 加入原因；
   - 团伙：成员数 + 设备数 + 团伙特征；
   - 设备风险：模型名 + 命中分 + 触发特征明细（满足需求2）；
   - 跨机构名单：所属机构 + 名单类型 + 命中数/命中率；
   - 评分模型：业务场景 + 评分阈值；
   - 核验：核验项清单（项名→条件→动作）。
5. **状态操作块**：因为状态来自业务流程，这里的"启用/停用"实际是**推进关联流程的状态**（已上线↔已下线）。改流程状态，规则状态随之变。
6. **数据来源标签**：本页所有数据标橘（样例JSON）；流程状态也标橘（来自业务流程样例）。

## 7. 需求1 · 跨机构名单（作为类型，命中率落到详情页）

你之前那条"综合需求1"说要一个"跨机构名单网络"矩阵视图（机构 × 名单类型 命中率）。但它和你说的"只留一个列表、跨机构当类型"其实可以统一，**不需要第二个页面视图**：

- **跨机构名单 = 规则类型之一**：在统一列表的"规则类型"列里就是一个值（见第5/6节类型6）。列表就是唯一视图，不需要页签、不需要工具栏切换。✅ 满足你说的"一个页面一个视图""跨机构是个类型"。
- **命中率信息落哪**：不再单独做矩阵页面，而是**折叠进跨机构类型规则的详情页**（第4.2节第4块"类型专属·跨机构名单"：所属机构 + 名单类型 + 命中数/命中率）。点开某条跨机构规则，就能看到它命中了哪些机构、命中率多少——综合需求1 的"机构×名单 命中率"在此保留。
- **全机构横向对比大热力图（机构A vs 机构B 哪类名单命中最高）**：那是管理概览，默认不做（做了就变多视图，与你"一个页面一个视图"冲突）；若以后真要，再单独加一个视图。

数据来源标签：命中率若实时算 → 灰标；若样例写死 → 橘标。

## 8. 需求2 · 设备风险（规则组 + 模型命中明细）

**放在哪**：设备风险作为上面 10 种类型之一，在统一列表里就能看到（筛选"规则类型=设备风险"即等于原来的"设备风险规则组"）。

**模型命中明细怎么呈现**：
- 列表里设备风险类规则，命中条件列直接显示"模型名 / 命中分 / 触发特征"摘要；
- 点进详情页（4.2 第4块"类型专属·设备风险"）看到完整明细：模型名、命中分（如 0.92）、触发特征清单（模拟器、Root、群控特征…）；
- 这样就满足了"列出动态模型命中明细（模型名 / 命中分 / 触发特征）"。
