# 风控 SaaS · 三大报告与复核流程总览

> 本文汇总「信息核验」「信用风控」「欺诈识别（方案 4）」三大报告的功能内容与复核/处置流程，作为后续迭代的基准说明。
> 对应代码目录：`SaaS/src/console/`。数据层与状态机分别为各报告的 `*Report.ts` 与 `*Ops.tsx`。
> 欺诈识别的「状态—操作」权威矩阵另见 `fraud-scheme4-status-ops-matrix.md`（本文第 3.3 节与其一致）。

## 0. 三报告对比概览

| 维度 | 信息核验 | 信用风控 | 欺诈识别（方案 4） |
|---|---|---|---|
| 检测目标 | 申请人身份 / 材料真实性 | 还款能力与信用风险 | 欺诈风险（盗用、伪造、团伙、设备、行为） |
| 评分口径 | **信用值** = 100 − 欺诈分（越高越好） | **信用评分** 0– ♾️（越高越好） | **欺诈分** 0–100（越高越危险） |
| 列表入口 | `InfoVerifyList.tsx` | `specsCr` → `cr:pre-credit`（6 列） | `FraudScheme4List.tsx`（12 列） |
| 详情组件 | `PreVerifyDetail.tsx` | `CreditReportDetail.tsx` | `FraudScheme4Detail.tsx` |
| 数据层 | `infoVerifyReport.ts` | `creditReport.ts` | `fraudScheme4Report.ts` |
| 状态机 | `VerifyOps.tsx`（8 工单态） | 4 决策按钮（无显式状态机） | `FraudScheme4Ops.tsx`（10 处置态） |
| 评价方向配色 | 信用值 ≥80 绿 / ≥20 黄 / 否则红 | 信用评分 ≥75% 绿 / 45%–74% 黄 / <45% 红 | 欺诈分 低绿 / 中黄 / 高橙 / 极高红 |

三报告共用同一套 UI 外壳（顶部 `DetailHeader` + 主列 `Panel` 模块 + 右侧锚点导航），并复用「整体操作」合并表格与操作日志追加机制。

### 1.3 复核工作流（`VerifyOps.tsx`）

**系统自动审核 `SysResult`（4 态）**：`处理中` / `通过` / `拒绝` / `预警`

**人工工单 `WorkStatus`（8 态）**：`核验计算中` / `待确认` / `已确认` / `待审核` / `提交复核` / `复核通过` / `复核拒绝` / `强制放行`

**操作（6 种）**：`查看` / `报告确认` / `强制复审` / `提交双人复核` / `确认放行` / `确认拒绝`

**状态 → 操作 矩阵**：

| 系统结果 | 工单状态 | 可执行操作 |
|---|---|---|
| （任意，结果未出） | 核验计算中 | 查看（按钮置灰） |
| 通过 | 待确认 | 查看、报告确认 |
| 通过 | 已确认 | 仅查看 |
| 拒绝 | 待确认 | 查看、报告确认、强制复审 |
| 拒绝 | 已确认 / 强制放行 | 仅查看 |
| 预警 | 待审核 | 查看、提交双人复核 |
| 预警 | 提交复核 | 查看、确认放行、确认拒绝 |
| 预警 | 复核通过 / 复核拒绝 | 仅查看 |

**状态流转**：报告确认 → `已确认`；强制复审 → `强制放行`（双人审批）；提交双人复核 → `提交复核`；确认放行 → `复核通过`；确认拒绝 → `复核拒绝`。高敏感操作（强制放行）须初审 + 终审主管两级。

## 4. 三报告共性设计约定

- **UI 外壳**：`DetailHeader` + 主列 `Panel` 模块 + 右侧锚点导航（`navCards`）。模块区以中文序号 Panel 组织，右侧锚点一一对应。
- **标签三体系**（`src/components/ui.tsx`）：
  - `Badge`：浅底描边胶囊（柔和，用于风险等级 / 信用结论等）。
  - `DecisionTag`：实色填充胶囊（醒目，用于自动审核 / 自动决策）。
  - `StatusTag`：描边 + 前置圆点（沉稳，用于人工审核 / 人工处置状态）。
- **颜色语义**：信用类（信息核验信用值、信用风控评分）越高越好，绿=优、红=劣；欺诈类（欺诈分）越高越危险，绿=低、黄=中、橙=高、红=极高。二者概念不同、配色取反，刻意不混用。
- **复核弹窗与日志**：各报告复用「整体操作」合并表格 + 操作日志追加（`addLog`）。高敏感操作（强制放行 / 加入黑名单 / 双人复核办结）须初审 + 终审主管两级审批。
- **数据驱动**：各报告数据层（`*Report.ts`）提供样例报告，列表 → 详情经 URL 参数（`sys` / `work` / `op` / `id`）衔接；状态机 / 列表 / 详情三处口径保持一致。
- **豁免附件**：规则豁免与卡片豁免共用 `ExemptModal`，必须上传附件方可提交，附件名写入操作日志。
