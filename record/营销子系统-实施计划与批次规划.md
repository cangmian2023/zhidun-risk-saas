# 数字营销子系统（dm）实施计划与批次规划

> 资料来源：`saas/record/qixin/`
> 现状：项目中 `dm` 子系统仅 `menus.ts` 里有一份旧的空菜单（工作台/猎客雷达/猎客信使/RTA服务），无任何页面组件。本次按你给的资料**全量重建**。

## 一、资料盘点

| 类别 | 文件 | 说明 |
|---|---|---|
| 菜单规格 | `营销子系统目录` | Vue/Element-UI 侧边栏 DOM 快照，含 5 个一级分组 |
| 营销页面 | `营销 - *`（50 个） | 各菜单页/下钻页的渲染快照（DOM dump），非设计稿 |
| 企业档案 | `企业档案 - *`（18 个） | 所有"企业"按钮跳转的详情页，被多页复用（含风控财产线索） |
| 首页 | `首页` | 1 个总览页 |
| 噪点 | `风控 - *`、`风控子系统目录` | 0 字节空文件，不在本次范围 |

**格式本质**：这些是真实产品的 HTML 渲染快照。要在本项目（React + 现有 UI 原语）"一比一复刻"，做法是**解析结构 → 用 `PageShell/Panel/DataTable/StatCard` 重建布局与表格列 → 填入代表性样例数据**，而非把 HTML 原样搬进 React。

## 二、菜单结构（需重建 `dmMenu`，5 组 / 26 个一级叶子）

- **潜客挖掘(9)**：AI营销、全维搜索、区域商机、地图拓客、网格营销、企业库、集团户、招投标、供应链
- **专题营销(5)**：科创金融、产业金融、园区金融、绿色金融、乡村振兴
- **营销管理(3)**：营销名单、营销线索、营销看板
- **存客管理(2)**：存客商机、客群分析
- **金融工具(7)**：PE/VC、上市数据、债券数据、主体评级、同业分析、行业研报、金融法规

加上下钻页，营销侧共需建 **50 个组件**；企业档案 **18 个组件**；合计 **约 68 个页面文件**。

## 三、工作量评估（按 DOM 体积/表格数/标签页数分层）

- **轻量（~10）**：AI营销、网格营销、集团户(入口)、乡村振兴、主体评级-历史评级、行业研报、区域商机-公司商机、基金投资路径-股东持股、开发区详情-商机线索
- **中等（~30）**：产业金融、供应链、债券数据、上市数据、主体评级、客群分析、存客商机、营销名单、营销看板、营销线索、同业分析、图上企业、企业库、区域商机(AI触达/关联营销)、集团户(国企/外资/央企/民营/机构/实际控制人/详情)、科创金融、绿色金融、营销名单-详情-数据看板、PEVC(投融资事件/投资机构/基金列表)、企业档案多数下钻页
- **重型（~28）**：全维搜索(2.2MB/1254表)、园区金融系列(1.5–6MB)、科创企业库(1.2MB)、企业库-列表(295KB)、营销名单-详情(620KB)、营销线索(616KB)、企业档案-基本信息(516KB)/经营/司法/历史、绿色金融(253KB)、地图拓客(140KB)

**关键难点**：少数超大数据页（如开发区详情 6MB/10911 个表实例）。按本项目"Demo 演示系统"定位，**重建为结构化、有代表性的复刻**（真实分区/标签页/表格列 + 样例行），不逐表逐行搬运——这既符合现有项目"本地样例 JSON"惯例，也避免无意义的 1 万行堆砌。

## 四、缺口与风险

1. **招投标**：菜单有，但 `record/qixin/` 下**无对应资料文件** → 需占位骨架或你补资料。
2. **0 字节空文件**：`同业分析 - 详情`、`企业档案 - 企业图谱 - 股权结构` → 无内容可复刻。
3. **疑似重复/误拷**：`金融法规`(1,234,447B) 与 `科创金融 - 科创企业库`(1,234,447B) 字节数完全相同；`PEVC 基金投资路径-历史股东持股` 与 `-对外投资` 同为 150,150B。复刻时按"同模板参数化页"处理，并需你确认金融法规内容是否正确。
4. 现有 `dmMenu`（旧 4 组）需整体替换为新结构，并同步改 `Console.tsx` 的 `MENU_ICON` 与分发链。

## 五、复刻方式与现有项目保持一致

- 布局：`PageShell` + `Panel` + `DataTable` + `StatCard`，三色来源标签 `<Cfg>/<Sam>/<Cal>`。
- 数据：每个模块一套 `dm*.ts`（类型+SEED）走本地 JSON，`/api/load-dm` `/api/save-dm`（沿用 Mid 模式）。
- 路由：`Console.tsx` 分发链补 `dm:*` 分支；`menus.ts` 重建 `dmMenu`。
- 企业档案：`DmEntArchive` 共享详情组件，被各"企业"按钮跳转复用（与风控财产线索共用）。

## 六、批次规划（每批交付：菜单接入 + 组件 + 样例数据 + 可点自测）

- **阶段 0 · 基座**：替换 `dmMenu`(5 组/26 叶子)、补 `MENU_ICON`、建 `dmStore`+样例 JSON 端点、分发链接空组件骨架、统一面包屑/Dm 布局壳。→ 让整套菜单可导航。
- **阶段 1 · 轻量页（快速出成果）**：AI营销、网格营销、集团户入口、乡村振兴、主体评级+历史评级、行业研报、区域商机-公司商机、基金路径-股东持股、开发区详情-商机线索。
- **阶段 2 · 潜客挖掘组**：全维搜索、区域商机(3)、地图拓客、企业库+列表、集团户(7)、供应链、（招投标占位）。
- **阶段 3 · 专题营销+营销管理+存客管理**：科创金融+科创企业库、产业金融、园区金融(4)、绿色金融、营销名单(3)、营销线索、营销看板、存客商机、客群分析。
- **阶段 4 · 金融工具**：PE/VC(6)、上市数据、债券数据、主体评级、同业分析(+详情)、行业研报、金融法规。
- **阶段 5 · 企业档案详情（18 页共享）**：基本信息/经营/司法/历史/新闻舆情/经营风险/财产信息/集团信息(+查看图谱)/企业图谱(7 个子页)。

## 七、待确认（见提问）

1. 复刻精度：Demo 结构性复刻（推荐）/ 尽量全量数据。
2. 启动批次：阶段 0+1（推荐）/ 先做某个旗舰重页 / 仅评审计划先不写码。
3. 缺口处理（招投标、2 个 0 字节页、金融法规疑似重复）：占位骨架（推荐）/ 暂跳过 / 你补资料后做。
