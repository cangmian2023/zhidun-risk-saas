
# Tab4 融合处置策略｜字段级完整功能设计
先理顺整条数据流，解决你看不懂的根源：
> Tab2输出：`predict_prob`（0~1原生概率）
> Tab4上区第一步：**概率 → 标准分映射**（公式/分段表）得到 `standard_score`
> Tab4上区第二步：**标准分分段阈值** 产出 `risk_level`（低/中/高风险）
> Tab3并行输出：`risk_signal_list` 多条风险标签
> Tab4下区：使用 `risk_level + risk_signal_list` 融合运算，产出最终处置结果

## 前置全局约束（写进PRD）
1. 本Tab所有配置**属于业务策略层，不属于模型内核**；修改不需要重新发布Tab2算法模型。
2. 执行顺序固定，不可调换：
概率映射 → 生成分数 → 分数划分等级 → 等级+标签融合决策
3. 优先级模式二选一全局生效：
- 模式A：**标签优先（强规则拦截）**
  只要命中高优先级黑名单/严重欺诈标签，直接覆盖分数等级，优先执行标签对应的处置
- 模式B：**分数优先**
  先以分数等级作为基准，标签仅做补充、人工复核提示，不推翻分数结论

# Tab4页面整体分区
## 【区块A：全局策略基础配置】（页面顶部，全局开关）
| 字段名称 | 字段类型 | 选项/填写说明 | 作用 |
| ---- | ---- | ---- | ---- |
| strategy_name | 文本 | 自定义策略名称，例如「智能察分V2.4处置策略」 | 策略唯一命名，用于版本管理 |
| priority_mode | 单选下拉 | 1-标签优先模式 / 2-分数优先模式 | 全局融合逻辑总开关 |
| default_decision | 下拉选择 | 通过 / 转人工审核 / 直接拒绝 | **兜底处置**；模型异常、特征缺失、无法计算时返回该结论 |
| strategy_status | 开关 | 启用 / 停用 | 策略启停 |
| valid_start_time | 日期时间 | 定时生效 | 支持策略定时切换 |
| valid_end_time | 日期时间 | 可为空 | 策略过期时间 |

> 输出元信息（只读展示，不可编辑）
> strategy_version：策略版本号；update_user；update_time

## 【区块B：上区域｜概率 ↔ 标准分映射配置】
目标：输入 predict_prob（0~1）→ 输出 standard_score（对外标准分）
两种映射方式，**二选一配置**
### 方式1：分段映射表（最常用，对标同盾商业化评分）
| 序号 | prob_min(包含) | prob_max(不包含) | standard_score | 备注 |
| ---- | ---- | ---- | ---- | ---- |
| 1 | 0.00 | 0.10 | 5 | 欺诈概率极低 |
| 2 | 0.10 | 0.30 | 25 |
| 3 | 0.30 | 0.70 | 60 |
| 4 | 0.70 | 1.00 | 92 | 欺诈概率极高 |

支持操作：新增行、删除行、上下调整、区间自动校验（禁止区间重叠、禁止断层）

### 方式2：线性公式映射
公式配置输入框：`standard_score = f(predict_prob)`
示例（智能察分0~100）：
`standard_score = Round(predict_prob * 100)`

> ⚠️ 校验规则：
配置完成后提供【预览按钮】，输入prob=0.5，实时算出对应的标准分，验证映射是否符合预期。

## 【区块C：上区域第二部分｜标准分 → 风险等级分段配置】
输入standard_score → 输出risk_level（风险等级编码+名称）
示例以【智能察分 0~100】举例
| 序号 | score_min(包含) | score_max(包含) | level_code | level_name |
| ---- | ---- | ---- | ---- | ---- |
| 1 | 0 | 30 | LOW | 低欺诈风险 |
| 2 | 31 | 70 | MID | 中等欺诈风险 |
| 3 | 71 | 100 | HIGH | 高欺诈风险 |

约束：区间连续、无重叠；
> 到这里，上半区整条链路闭环：
`predict_prob → standard_score → risk_level`

## 【区块D：下区域｜融合决策规则表（核心！等级 + 标签联合判断）】
> 逻辑说明：
系统先算出基础 `risk_level`；同时存在一组命中标签 `risk_signal_list`
融合规则支持两种匹配逻辑，由顶部 `priority_mode` 控制。

### 字段清单【融合决策规则明细表，可多行配置】
| 字段 | 类型 | 说明 |
| ---- | ---- | ---- |
| rule_sort | 数字排序 | 规则从上至下依次匹配，命中即终止匹配 |
| base_risk_level | 多选下拉 | LOW / MID / HIGH；可多选，表示本条规则适配哪些基础等级；选择【全部】代表所有等级都生效 |
| match_tag_list | 多选（引用Tab3已定义的风险标签） | 支持两种匹配方式单选：<br>• 全部命中：所选标签必须同时存在<br>• 任意命中：存在任意一个标签即满足条件 |
| tag_severity | 标签严重等级（只读，跟随Tab3配置） | 轻度 / 中度 / 重度，辅助运营识别 |
| final_decision | 下拉 | 通过 / 转人工审核 / 直接拒绝 |
| process_id | 下拉选择（关联业务流程库） | 选择处置后对应的业务流程：<br>例：拒绝→自动拒绝流程；转人工→信审人工复核流程 |
| output_remark | 文本 | 对外报文附带处置说明，用于接口返回、审核页面展示 |
| is_active | 启用开关 | 临时关闭单条规则，无需删除 |

### 举两条配置样例直观看懂
场景：priority_mode = 标签优先
规则1：
base_risk_level =【全部等级】
match_tag_list =【团伙设备申请、身份证黑名单】匹配方式：任意命中
final_decision = 直接拒绝
process_id = P005 黑名单拒绝流程
> 含义：无论分数算出是低风险还是中风险，只要命中这两个标签其一，直接拒绝

规则2：
base_risk_level = MID（中等风险）
match_tag_list =【短期多头借贷】任意命中
final_decision = 转人工审核
process_id = P002 普通人工复核流程

### 兜底逻辑
所有融合规则遍历完成，**没有任何一条规则匹配成功**：
直接使用「基础risk_level对应的默认处置」
你需要额外配置一张【等级默认处置映射表】

## 【附属配置表：基础等级默认处置映射表（必不可少）】
当没有任何标签触发融合规则时，使用本表给出结论
| base_risk_level | 默认处置结论 | 绑定业务流程ID |
| ---- | ---- | ---- |
| LOW | 通过 | P001自动通过流程 |
| MID | 转人工 | P002人工复核 |
| HIGH | 拒绝 | P003高风险自动拒绝 |

# 整条链路变量流转汇总（方便你和前后端对齐）
## 输入变量（来自上游Tab2、Tab3）
1. `predict_prob`：模型内核输出概率（0~1）
2. `risk_signal_list`：命中标签数组 [{"tag_code":"","tag_name":""}]
3. `top_feature_list`：关键解释特征（仅附带展示，不参与Tab4运算）

## Tab4内部计算中间变量（页面调试可见，对外非必输出）
1. `standard_score`：概率映射后的标准分
2. `risk_level`：标准分划分后的基础风险等级

# 帮你区分容易混淆的边界（解决你的理解障碍）
1. **概率→标准分**：只是数值换算，没有业务判断；
2. **标准分→风险等级**：单纯分数分层；
3. **等级+标签融合决策**：真正的业务审批判断；
4. 如果不做下区融合决策，系统只会单纯依靠分数等级自动处置；
5. 引入标签融合，就是实现：**强规则可以修正分数结论**，也是市面上同盾、神策风控产品标准设计。
