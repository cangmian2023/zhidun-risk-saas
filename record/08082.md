## 一、公共能力（跨页面统一架构）

### 1.1 列表表格 DataTable（需求 15）
- 列支持 `fixed: 'left' | 'right'` 固定：左侧固定列 sticky left-0；右侧固定列 sticky 并自动让出「操作」列宽度（ref 实测偏移）。
- 首列默认左固定（兼容历史页面）；操作列始终右固定。
- 列级自定义渲染 `render` 优先于类型渲染（需求 14 全站修复）。

### 1.2 流程状态组件（需求 13/16/22，全站同一套）
- `FlowStateCell`（列表单元格）：状态 pill + 流转按钮，按 对象自身 flowKey/flowState 显示；支持 `matchObj`（对象字段）匹配具体流程。
- `FlowActionBar`（详情操作条）：流程名 + 当前状态 + 操作按钮，按钮点击弹确认后流转状态。
- 流程节点状态机：
  - 每个节点：状态名 / 操作按钮（终态留空）/ next（自动重算）。
  - **节点时限（需求 14→22）**：时限倒计时属性在**节点属性面板**配置（分钟，空=不限制），**不在状态机配置区**；运行时按当前状态匹配节点取时限。
  - 状态配色：待→橙 / 中→蓝 / 已→绿 自动推导。

### 1.3 业务流程匹配（需求 16，一条配置 → 多条具体流程）
- **一条业务流程配置（FlowItem）下挂多条具体流程（flowGraph）**，运行时按对象字段值匹配。
- 每条具体流程 = 名称 + 关联字段（可选）+ 独立状态机 + 画布图 + 节点属性。
- 匹配规则：
  1. 精确命中：`match` 非空且所有条件满足（行间 AND，值逗号分隔多选）；
  2. 兜底：无 match（不关联 = 该页面所有数据都关联本流程）的第一条 flowGraph；
  3. 都没有 → 无匹配，流程状态显示「—」（方案 B）。
- 状态机归属：彻底下沉到每条具体流程（配置级状态机入口删除，旧数据重新配）。

### 1.4 样例数据本地 JSON（全项目约定）
- 所有页面样例数据存本地 `src/console/*.json`，经 `/api/save-*` `/api/load-*` 持久化，首启动 SEED 自动落盘。
- 新增模块沿用；SEED 增字段后删旧 JSON 重落盘。

## 二、贷中监控 · 使用域（cr）

- **读取页面配置** midDashboards.json（db-100，key=`cr:overview`）+ 本地样例 JSON 渲染，**不写死**。

### 2.2 预警工作台（预警队列）cr:mid-alert-workbench（需求 7/8/13/14/15）
- **数据读 midAlerts.json（橘）**，禁止写死；26 条样例 = 12 类型 × 红/黄 + 机会 4 条（含 flowKey/flowState/flowStateAt）。
- 顶部统计卡：预警总数 / 红灯 / 黄灯 / 机会（按等级统计，**不做状态统计**）。
- 筛选：等级 / 预警类型（带计数）/ 触发场景。
- 列（含固定）：
  | 列 | 说明 |
  |---|---|
  | 预警ID / 客户 / 预警类型 / 触发场景 / 等级 / 命中规则 / 指标值-阈值 / 预警时间 | 基础信息 |
  | 时限倒计时 | 需求 14：按 flowStateAt + 节点时限实时计算，每分钟刷新；超时红 / 30min 红 / 2h 橙 / 终态·无时限 — |
  | 流程状态（fixed:right 倒数第二列） | 需求 13/15：状态 pill + 流转按钮（FlowStateCell，按 matchObj 匹配具体流程） |
  | 操作（右固定） | 仅「查看」→ 进预警详情（**不重复流程按钮**，需求 15） |
- 行点击进详情；操作列「查看」按钮同行为。

### 2.3 预警详情 cr:mid-alert-detail（需求 10/17/18/23）
- **顶部 FlowActionBar**：按 flowKey+flowState 关联业务流程，显示流程名 + 当前状态 + 操作按钮；点击流转状态并**写操作日志**（需求 18）。
- **预警信息**（需求 23 拆分）：仅基本信息——预警ID/客户/预警类型/等级/预警时间/命中规则/指标值-阈值/流程状态/匹配流程；附等级徽章 + 节点时限徽章。
- **原始数据与规则详情**（需求 23，独立区块）：
  - 规则详情：规则名称 / 规则类型 / 触发条件 / 统计口径 / 判定结果（指标值 op 阈值→命中）/ 适用产品（按预警类型映射）。
  - 原始数据明细表：按预警类型构造触发记录（负债激增→放款明细、司法涉诉→执行案号、设备异常→设备/IP、回访失联→失联记录等）。
- **客户摘要**（需求 17）：
  - 按 `custId` 匹配 midCustomers.json（修复 cust_id/custId 字段不一致导致的空页面）；
  - 客户档案覆盖全部预警客户（19 个，含产品/授信/在贷/风险等级/历史预警/历史处置）；
  - 「查看单客视图 →」按钮在摘要区块右上角（需求 17），带来源参数（`&id=预警ID`，供单客返回）。
- **处置记录**（需求 18，原「处置工单」改名）：
  - 流程按钮每次点击 → 写操作日志：谁（操作人）· 何时 · 做了什么（状态流转 X→Y），落盘到关联工单 logs；
  - 无关联工单自动新建处置记录；显示关联处置工单列表（点击进处置详情）。

### 2.4 单客视图 cr:mid-single-cust（需求 19/20）
- **返回按钮**（需求 19）：从预警详情进入则返回该预警详情（URL 带 `id=` 来源）；直接进入则回预警队列；**删除「前往预警工作台」按钮**。
- Header：姓名 + 客户号 + 产品 + 风险等级徽章。
- 关键指标卡：授信额度 / 在贷余额 / 额度使用率（实时计算灰）/ 贷款状态。
- 基础画像 + 行为分趋势（近 6 月 vs 同客群均值折线）。
- **关联图谱**（需求 20）：SVG 手绘——客户居中，关联实体环绕（企业/共借人/设备/联系人，颜色区分），连线标关系，高危实体红框/红色虚线；附图例。

- 预警时间线（等级色点 + 命中规则）+ 处置记录（工单卡片 + 历史处置，操作人/备注）。

### 2.5 处置工单 cr:mid-dispose-workbench（保留）

- **详情页**：
  - 关联页面（PagePicker 多选）；
  - **具体流程列表**：每条流程显示 名称 + 关联条件摘要（`关联：level=RED 且 alert_type=司法涉诉…` 或「不关联（全部数据）」）+ 状态机节点数 + 画布图摘要；操作（编辑·删除）；「＋ 添加流程」。
- **画板弹窗**（FlowCanvasEditor，需求 16 输入顺序）：
  1. **流程名称**（新建给默认值）；

  3. **状态机**（本流程独立，默认三节点 待处理→处理中→已处理，可一键填充）：状态名 / 操作按钮 / 增删节点；
  4. **画布图**：节点增删拖拽连线（start/normal/end）；
  5. **节点属性面板**：标题 / 按钮名称 / **时限分钟（需求 22）** / 经办角色 / 审核事项 / 审批结果→状态映射 / 审批意见预设 / 附注。
- 新建流程弹窗：名称 + 关联页面（**不再有配置级状态机输入**）。

## 四、评分产品子系统（需求 21 · 重新规划，方案待拍板）

### 现状问题
- 21 项菜单按"产品"切分，同一客户数据在三个产品间割裂，故事线讲不通；
- query/monitor 页面大量同质化；监控/批量是平台能力却被各产品复制。

### 重规划方案（1 对象 + 6 产品页 + 4 平台页 = 11 页）
| 层 | 页面 | 功能 |
|---|---|---|
| ① 对象视角 | 对象评分档案（1 页） | 输入申请人 → 智察/智信/智融三分数并排 + 决策，可下钻各产品明细（替代原总览） |
| ② 产品视角 | 智察分：欺诈评分查询 | 欺诈分+概率+决策；下钻规则命中明细 / 黑名单与团伙 |
| | 智察分：欺诈监控与调优 | 新客欺诈率、通道欺诈率、命中 TOP 规则趋势 |
| | 智信分：违约评分查询 | 信用分+违约概率+等级；下钻评分卡解释 / 额度与拒绝建议 |
| | 智信分：客群分布与 Vintage | 分档通过率、Vintage 逾期曲线、评分分布 |
| | 智融分：融合评分查询 | 综合分；下钻融合构成（双维引用+价值）/ 场景对比 / 360 风险×价值 |
| | 智融分：场景效果监控 | 各场景转化率 / 命中率 / 用信情况 |
| ③ 平台能力 | API 对接（1 页） | 一次对接三产品、鉴权、调用日志 |
| | 批量评分（1 页） | 文件上传→任务队列→结果下载 |
| | 计费与账单（1 页） | 三产品统一账本、充值、余额、月度账单 |
| | 模型监控告警中心（1 页） | 三产品 monitor 合并，按产品 Tab 切换 |

- **砍掉**：各产品重复 monitor 页、独立客户分层页（并入智融 360）、冗余 tier 页。
