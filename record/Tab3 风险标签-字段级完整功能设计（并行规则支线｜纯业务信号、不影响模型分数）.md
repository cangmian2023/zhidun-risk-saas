# Tab3 风险标签\-字段级完整功能设计（并行规则支线｜纯业务信号、不影响模型分数）

## 一、Tab3 核心架构铁律（固定、不可改）

**1\. 运行机制：与Tab2模型推理完全并行执行**

**2\. 绝对隔离：所有标签、规则、名单碰撞 不参与概率计算、不改变标准分、不影响模型内核**

**3\. 唯一产出：业务风险信号标签（用于解释、监控、Tab4融合决策）**

**4\. 所有规则复用公共决策引擎资源，不重复造规则**

## 二、Tab3 页面整体结构

页面分为 3 大模块：

1. **全局配置**：标签整体策略、冲突策略、执行开关

2. **标签明细配置列表**：每一条风险标签的独立规则、绑定条件、属性

3. **实时输出预览**：当前模型最终输出标签结构（给前端对接、调试用）

## 五、关键逻辑定义（解决你之前所有疑惑）

### 1\. 为什么标签不影响分数？

Tab3 是 **独立并行支线**，执行链路不进入 Tab2 模型推理流程。

模型概率、标准分全部由 Tab2\+Tab4 上半区算出，标签完全不参与计算。

### 2\. 标签的唯一两个作用

- **业务解释作用**：告诉用户/审核人，模型为什么风险高（合规可解释）

- **辅助决策作用**：送入 Tab4 做【等级\+标签融合处置】

### 3\. 两种标签彻底隔离（系统自动区分）

- **决策型标签**：join\_fusion\_switch=true → 参与最终审批结论

- **监控型标签**：is\_risk\_monitor\_tag=true、join\_fusion\_switch=false → 只用于模型PSI/KS监控、样本分析、调优，不干预业务结果

## 七、完整运行链路（终版、可写进架构文档）

**并行双主线**

主线A（模型打分）：特征 → Tab2算法 → predict\_prob → Tab4映射分数、等级

主线B（标签信号）：特征/名单 → Tab3并行规则引擎 → risk\_tag\_list

最终合并：分数等级 \+ 标签列表 → Tab4融合 = 最终业务结论
