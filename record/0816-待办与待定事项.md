# 企业风控子系统 · 待办与待定事项（2026-08-16）

## 一、本轮已完成（审批流程配置驱动化改造）

| 审批点 | 原实现 | 现实现 |
|---|---|---|
| 决策引擎·审批管理（de:approval-manage / approval-detail） | 行级「通过/驳回」按钮页面硬编码；flowId 指向不存在的流程（de_model_publish 等），流程列形同虚设 | 接入管理中心业务流程「决策引擎上线审批流程」（f-de-approve），操作按钮由流程配置驱动，流转同步审批状态 |
| 催收·减免审批（协商减免与回款） | 「通过/驳回」纯页面硬编码，无流程概念 | 接入管理中心业务流程「减免审批流程」（f-dun-waiver），操作按配置渲染 |
| 报告模块审批（信息核验/信用/欺诈/决策报告） | 弹窗内容由报告模板的审核流程配置驱动（管理中心-报告模板可配），非页面硬编码 | 保持现状（配置驱动），**但未走 bizFlows**，见 P0-5 |

## 二、待拍板的 P0 合规项

1. **流程操作是否强制填意见**——建议：驳回必填、其余可选（演示系统每个操作都要打字会卡操作）。
2. **权限体系**——要不要做「角色切换器」模拟（风控主管/运营/客户经理）：角色怎么分、数据隔离到哪一步（仅展示隔离 or 真过滤）、敏感操作二次校验用什么方式（模拟验证码弹窗？）。
3. **PDF 报告导出 + 水印**——水印带什么：机构名（写什么？如"演示银行"）、操作人、导出时间；画像/决策追踪导出成什么形态（浏览器打印视图？）。
4. **模型/规则修改审批流**——审批人角色用谁、未复核是否真的不生效（当前模型只读，要先开「编辑」入口）。
5. **报告模块审批是否统一迁到管理中心-业务流程（bizFlows）**——现在报告审批走「报告模板审核流程配置」体系（审核事项/审批结果/意见预设很细），迁 bizFlows 会简化配置项；不迁则保持两套配置体系并存。

## 三、待拍板的 P2 剩余

1. **企业关联图谱多层穿透**——二级以上股权/担保关系 + 风险传导链计算（当前只做了一级关联网络）。
2. **报告导出真 PDF**——带水印（与 P0-3 关联）。

## 四、其他待确认

1. **监控名单 / 名单管理是否撤掉预置流程**（现在是预置在管理中心业务流程里，用户可自行删改；确认是否保留）。
2. **预警处置工作台 / 决策事件**的预置流程是否保留（当前为演示效果预置，建议保留）。
