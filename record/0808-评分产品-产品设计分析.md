# 评分产品（智察分 / 智信分 / 智融分）· 产品设计分析 v2

> 文档性质：AI 分析稿（用户原稿见 `record/0808.md`）。本稿为 1.1 功能分析与 1.2 菜单设计 v2，不含代码。
> 设计原则（v2，用户拍板框架）：**一个对象、两个维度、一层融合、三个场景**——
> 三产品不是三个并列的孤立产品，而是同一评价对象的**完整评分体系**：
> 差异在维度（智察防欺诈 / 智信看违约），整体在对象（同一申请人贯穿所有评分），融合在智融（双维之上叠价值、向下裂变三场景）。

---

## 0. 设计框架：一个对象 · 两个维度 · 一层融合 · 三个场景

```
                       ┌─────────────────────────────────────────┐
                       │        评价对象（申请人 · 同一主体）        │
                       │   身份证/手机号/设备 —— 所有评分都针对他     │
                       └─────────────────────────────────────────┘
                                        │
              ┌─────────────────────────┼─────────────────────────┐
              │  两个维度（基础层·并列互补） │                         │
        ┌─────▼─────┐            ┌─────▼─────┐                     │
        │  智察分    │            │  智信分    │                     │
        │ 欺诈维度   │            │ 违约维度   │                     │
        │ 0~100越高越│            │ 300~900越 │                     │
        │ 危险       │            │ 高越安全   │                     │
        └─────┬─────┘            └─────┬─────┘                     │
              │  引用欺诈维度            │  引用违约维度              │
              └───────────┐   ┌─────────┘                          │
                          ▼   ▼                                    │
                   ┌──────────────┐                                │
                   │  一层融合     │  智融分 · 综合                  │
                   │ 风险(双维)×价值 │  300~900 风险×价值双维          │
                   └──────┬───────┘                                │
              ┌───────────┼───────────┐                            │
        ┌─────▼─────┐ ┌───▼─────┐ ┌───▼─────┐                     │
        │ 违约风险审核│ │ 授信转化 │ │ 借贷兴趣 │                     │
        │ 场景(风控) │ │ 场景(转化)│ │ 场景(经营)│                    │
        └───────────┘ └─────────┘ └─────────┘                     │
                                                                  │
  整体性：评分产品总览 = 同一申请人的三个分数并排展示（对象档案视角）    │
  融合性：智融分页面显式展示"由什么融合而来"（双维引用 + 价值维度）      │
  ──────────────────────────────────────────────────────────────────┘
```

**四个词的业务含义**：
- **一个对象**：所有评分围绕同一申请人（主键身份证），三个分数是"同一个人的三份体检报告"，不是三个人的评分。
- **两个维度**：智察分（欺诈）、智信分（违约）是并列的**基础风险维度**，独立建模、互不包含，共同构成"风险"轴。
- **一层融合**：智融分在双维之上叠加**价值维度**（借贷兴趣/转化意愿/资产），融合成"风险×价值"综合分。
- **三个场景**：智融分模型向下按业务视角裂变为三个场景输出——违约风险审核（风控）、授信转化（转化）、借贷兴趣（经营）。

## 1.1 功能分析：完整评分体系下，客户需要什么、怎么用

### 1.1.1 角色
风控审核员（查单）、风控策略/模型岗（配规则、盯效果）、IT 对接岗（接 API/批量）、财务/运营岗（账单/客群）。

### 1.1.2 整体性能力（体现"一个对象"）

| 能力 | 说明 | 页面形态 | 体现 |
|---|---|---|---|
| **对象评分档案** | 输入一个申请人 → 同时看到 智察分/智信分/智融分 三份分数并排，一键跳各详情 | 档案卡（三仪表并排 + 各维度结论） | 一个对象贯穿所有评分 |
| 评分产品总览 | 三产品调用量/命中率/异常/场景使用一屏总览 | 总览看板 | 体系整体视图 |
| API 对接 / 批量评分 | 一次对接三个产品（单接口按需返回分数组合） | 对接页 | 体系统一入口 |
| 计费与账单 | 三产品统一账本 | 账单页 | 体系统一账务 |
| 监控告警中心 | 三产品 PSI/命中率/稳定性统一告警 | 告警中心 | 体系统一监控 |

### 1.1.3 差异性能力（体现"两个维度"）

**智察分 · 欺诈维度（防守）**

| 功能 | 说明 | 使用者 |
|---|---|---|
| 欺诈评分查询 | 输入标识 → 欺诈分(0~100) + 欺诈概率 | 审核员 |
| **规则命中明细（还原）** | 逐条还原命中规则（规则名/命中值/权重/贡献），解释"为什么判可疑" | 审核员/模型岗 |
| **黑名单与团伙库** | 手机号/设备/身份证/银行卡黑名单 + 团伙关联网络 | 模型岗 |
| 欺诈监控 | 新客欺诈率、通道欺诈率、命中 TOP 规则趋势 | 模型岗 |
| 欺诈模型调优 | 特征新增/切点调整（欺诈样本驱动） | 模型岗 |

**智信分 · 违约维度（准入）**

| 功能 | 说明 | 使用者 |
|---|---|---|
| 违约评分查询 | 输入标识 → 信用分(300~900) + 违约概率 + 信用等级(A-E) | 审核员 |
| **评分卡解释** | 拆解各评分项贡献，解释分数怎么来的 | 审核员/模型岗 |
| **额度与拒绝建议** | 建议额度档、拒绝阈值、拒绝原因 | 审核员 |
| **客群分布与逾期表现** | 分档通过率、Vintage 逾期曲线 | 模型岗 |
| 信用模型监控 | KS/AUC/PSI 稳定性 | 模型岗 |

### 1.1.4 融合性能力（体现"一层融合"）

**智融分 · 综合（融合层）**

| 功能 | 说明 | 使用者 |
|---|---|---|
| **融合评分查询** | 输出综合分 + 显式展示"融合构成"：违约维度(引用智信)、欺诈维度(引用智察)、价值维度(自有) 三块贡献 | 审核员/策略岗 |
| **场景评分对比** | 同一申请人 违约/授信转化/借贷兴趣 三场景分对比（同一模型×不同场景规则） | 策略岗 |
| **360 风险评估** | 风险(智察×智信)×价值 四象限矩阵 + 客户画像 | 策略岗 |
| **场景规则配置** | 三场景独立规则（违约拦截/提额候选/高兴趣触达） | 策略岗 |
| 客户分层 | 高价值/高风险/沉睡/活跃客群占比 | 运营岗 |
| 场景效果监控 | 各场景转化率/命中率/用信情况 | 策略/运营岗 |

### 1.1.5 场景层（体现"三个场景"）
违约风险审核 / 授信转化 / 借贷兴趣三个场景，在「场景评分对比」与「场景规则配置」中落地——同一智融分模型、三个业务视角、三套规则。

### 1.1.6 用户使用闭环
```
审核员：对象评分档案(三分数并排) → 智察规则明细 / 智信额度建议 → 做决策
策略岗：融合评分查询(看构成) → 360 矩阵 → 场景规则配置 → 监控告警 → 调优
IT岗：  一次对接三产品 API / 批量 → 调用日志
财务/运营：统一账单 → 客群分层 → 场景效果
```

## 1.2 左侧目录菜单列表（v2：差异 + 整体 + 融合）

> 结构与 v1 差异：新增**「对象评分档案」**作为体系总入口（整体性）；智融分菜单明确标注「融合」定位并显式包含"融合构成"（融合性）；三产品仍各有专属页面（差异性）；公共能力下沉。

> 合计 21 项：评分体系 2 + 智察分 5 + 智信分 5 + 智融分 6 + 公共 4。
> 与 v1 差异：新增「对象评分档案」（整体性入口）；智融分从"场景评分查询"升级为"融合评分查询 + 场景评分对比"（融合性显式化）；其余差异化页面保留。

## 附：v1 → v2 演进

| | v1（上一版） | v2（本版） |
|---|---|---|
| 定位 | 三个并列的独立产品 | 同一评价对象的完整评分体系 |
| 整体性 | 无（三产品各管各） | 新增「对象评分档案」：一对象三分数并排贯穿 |
| 融合性 | 智融分只做"场景对比" | 融合评分查询显式展示"融合构成"（双维引用+价值） |
| 差异性 | 三产品各有核心页（规则明细/评分卡/Vintage） | 保留并强化 |
| 菜单 | 20 项 | 21 项（+对象档案；智融分+1 融合查询） |
