# 智能策略引擎｜全策略业务流程 + 节点属性说明
> 当前列表策略清单：
1.新案智能分案
2.续案/回退分案
3.M0还款提醒策略
4.M1短信+外呼策略
5.M2外呼+函件策略
6.还款提醒短信模板（**模板资源，非执行策略**）
7.失联修复短信（**模板资源，非执行策略**）
8.委外移交流程
9.委外回款分账
10.诉讼立案策略
11.核销处置策略
12.失联修复分流
13.欺诈识别分流

> 重要区分：
- **执行策略**：会流转案件、执行动作、分支判断；
- **短信模板**：属于公共资源，不参与策略流程编排，在策略节点中被引用，要从策略列表剥离，归到【短信模板管理】页面，不要混在此列表。

## 通用：所有策略公共节点属性（统一标准）
> 每一个策略流程节点，都具备下面基础属性
|属性项|说明|
| ---- | ---- |
|节点类型|条件判断 / 执行动作 / 延时等待 / 子策略调用 / 结束|
|节点ID|系统唯一编码|
|节点名称|业务可读名称|
|进入条件|什么案件会流入本节点（逾期阶段、客户标签、金额、案件状态等）|
|超时配置|节点最大停留时长；超时之后走哪个分支|
|失败分支|节点执行失败时，案件流向|
|命中计数|流入本节点案件数、成功执行数、失败数（对接【策略执行监控】页面）|
|合规配置|是否启用合规拦截；禁止执行时间段；黑名单过滤|
|输出分支|多条出口分支，每个分支设置筛选条件，条件匹配则流向对应下一个节点|

## 1、新案智能分案策略
**业务定位**：全新入催案件，做首次分配，分配给坐席/AI/委外，是贷后第一个策略。
### 完整流程
1. 策略入口：新案件入催，触发本策略
2. 节点1：案件基础条件过滤（金额、逾期天数、客户标签、是否失联）
3. 节点2：分流判断分支
    - 分支A：高风险欺诈 → 流向【欺诈识别分流子策略】
    - 分支B：失联号码 → 流向【失联修复分流子策略】
    - 分支C：普通可触达M0 → 流向【M0还款提醒策略】
    - 分支D：满足委外准入 → 流向【委外移交流程】
    - 分支E：直接人工坐席分配 → 分配人工坐席，策略结束
4. 结束节点：记录分案结果，写入案件档案。

### 各节点属性
1）过滤节点：节点类型=条件判断
- 进入条件：新入催未分配案件
- 判断字段：逾期账龄、欠款本金、客户风险标签、号码连通状态
- 超时：无；失败分支 → 进入人工兜底分案
2）分流节点：节点类型=条件判断
- 输出5条业务分支；每条分支携带标签，传递给下游子策略
3）结束节点：节点类型=结束动作，落库案件归属信息

## 2、续案 / 回退分案策略
**定位**：案件从委外退回、坐席释放、策略回滚后，重新再分配。
### 流程
1.策略入口：案件状态为【待重新分案】（委外退回、坐席释放、策略回退）
2.节点1：回收信息读取（上一轮处置结果：PTP、失联、回款、投诉标记）
3.节点2：条件判断
    - 分支A：已经达成PTP → 进入PTP跟进延时策略
    - 分支B：已经完全失联 → 失联修复分流
    - 分支C：账龄升级到M1/M2 → 进入对应账龄催收策略
    - 分支D：继续委外处置 → 委外移交流程
    - 分支E：分配内部坐席处理
4.结束节点：更新案件当前处置归属

### 节点属性
- 特殊属性：读取**上一轮处置结果上下文**；支持继承原有案件标签；
- 失败兜底：无法匹配分支，流入人工队列。

## 3、M0还款提醒策略（账龄M0，刚逾期）
**定位**：轻度逾期，以短信提醒为主，低打扰。
### 流程
1.入口：M0账龄、可联系的逾期案件流入
2.节点1：合规校验（客户是否退订短信、禁止呼叫时段）
3.节点2：延时等待节点（逾期后N小时再发送，不要立刻触发）
4.节点3：执行动作节点：发送还款提醒短信（引用短信模板）
5.节点4：等待观察节点（等待N天，观察是否回款）
    - 分支A：已全额回款 → 策略结束，案件结案
    - 分支B：部分还款，未结清 → 继续停留M0周期
    - 分支C：到期未回款，账龄滚动M1 → 流转【M1短信+外呼策略】
    - 分支D：号码短信发送失败 → 标记弱触达，流向失联修复分流

### 关键节点属性
- 延时等待节点属性：等待时长；等待期间如果发生回款，直接跳出策略；
- 短信动作节点属性：引用模板ID、发送频次限制、退订拦截；

## 4、M1短信+外呼策略（账龄M1）
**定位**：逾期1‑30天，短信+AI外呼组合催收
### 流程
1.入口：账龄M1，由M0策略流转过来
2.节点1：合规过滤（客户投诉标记、禁呼名单）
3.节点2：执行动作：批量发送催收短信
4.节点3：延时；之后执行AI外呼动作节点（引用话术模板、呼叫频次、呼叫时间窗口）
5.节点4：呼叫结果判断
    - 分支A：客户全额回款 → 结案，策略结束
    - 分支B：客户承诺PTP → 挂PTP跟踪延时节点，到期校验是否履约
    - 分支C：接通但是拒绝还款 → 继续本策略循环有限次数
    - 分支D：多次呼叫失败、无人接听 → 标记失联，进入失联修复分流
    - 分支E：账龄滚动进入M2 → 流转【M2外呼+函件策略】

### 节点属性
AI外呼动作节点：
- 引用话术模板ID；最大呼叫次数；呼叫时间窗口；命中PTP是否自动登记；
PTP跟踪延时节点：等待至承诺还款日；到期校验履约状态，履约结案，未履约往下游流转。

##5、M2外呼+函件策略（账龄M2，逾期30‑60天）
**定位**：逾期加重，AI外呼、发催告函，评估委外/诉讼条件
###流程
1.入口：M1升级流转至M2
2.节点1：合规校验
3.节点2：AI外呼动作（提高呼叫频次）
4.节点3：条件判断，满足条件执行【发送催告函】动作节点（电子函件）
5.节点4：结果分流
    - A：全额回款 →结案
    - B：PTP承诺 →PTP跟踪节点
    - C：处置效果差，满足委外条件 →流向【委外移交流程】
    - D：满足诉讼门槛 →流向【诉讼立案策略】
    - E：持续失联 →失联修复分流
    - F：账龄继续恶化，进入M3，触发核销前置判断

###节点属性
函件动作节点：函件模板ID；发送方式（电子）；发送记录落库；

##6、委外移交流程策略
**定位**：案件移交外部催收机构，分配委外机构，下发案件，接收委外回传
###流程
1.入口：上游策略判断满足委外准入条件
2.节点1：准入条件校验（欠款金额、账龄、非诉讼中，合规黑名单过滤）
3.节点2：机构分配节点（按区域/负载率分配委外机构）
4.节点3：执行动作：案件推送给委外机构，下发案件资料快照
5.节点4：等待回传节点，等待委外作业回传反馈
    - 分支A：委外回传客户全额回款 →执行【委外回款分账策略】，案件结案
    - 分支B：委外回传PTP承诺 →PTP跟踪节点
    - 分支C：委外回传失联、处置无效 →案件回退，流入【续案/回退分案策略】
    - 分支D：超过最大委外周期未回款 →案件回退
###节点属性
等待回传节点属性：最大等待周期；接收委外回传数据；超时自动回退；
机构分配节点：负载率阈值、区域匹配规则。

##7、委外回款分账策略
> 注意：这是**后置业务动作策略，不是案件流转催收策略**，委外发生回款之后才触发。
###流程
1.入口：委外机构回传发生回款
2.节点1：读取案件委外协议（佣金比例、账期）
3.节点2：分账计算动作节点，计算机构佣金
4.节点3：财务校验节点；
    - 分支A：校验通过 →生成分账记录，同步财务模块；案件更新回款状态
    - 分支B：校验异常 →流入财务人工复核队列
5.结束节点：归档分账记录。
###节点属性
计算节点：读取协议参数；输出佣金金额；失败进入人工复核。

##8、诉讼立案策略
**定位**：案件达到诉讼标准，走立案前置处置
###流程
1.入口：上游策略流转，达到诉讼准入条件
2.节点1：诉讼准入条件判断（金额、账龄、材料完整性，排除不宜诉讼标签）
3.节点2：执行动作：整理诉讼案件材料快照
4.节点3：分流
    - A：材料完备 →移交法务，进入诉讼工作台，策略结束
    - B：材料缺失 →人工补材料队列
    - C：客户发生还款/PTP →终止诉讼流程，回到催收策略
###节点属性
条件节点：诉讼准入阈值；输出案件诉讼快照。

##9、核销处置策略
**定位**：确认损失，满足核销条件的案件处置流程
###流程
1.入口：案件长期失联、执行终本，达到核销条件
2.节点1：核销条件校验（账龄、追偿记录、穷尽处置手段标记）
3.节点2：审批流转节点
    - 分支A：审批通过 →执行核销动作，案件状态改为核销，归档案件快照
    - 分支B：审批驳回 →退回催收处置，回到续案分案
###节点属性
审批节点：多级审批配置；审批超时自动驳回；核销快照留存。

##10、失联修复分流策略
**定位**：号码失联，做号码修复，修复成功重新流入催收，修复失败走向委外/诉讼/核销
###流程
1.入口：上游策略标记号码失联
2.节点1：执行动作：启动号码修复查询
3.节点2：结果判断
    - A：修复出新有效号码 →更新客户联系方式，回退至【续案/回退分案策略】重新催收
    - B：修复失败无新号码 →继续判断，流向委外、诉讼或者核销前置
###节点属性
动作节点：号码修复调用；最大重试次数。

##11、欺诈识别分流策略
**定位**：识别疑似骗贷、欺诈客户，做特殊处置
###流程
1.入口：新案分案流入，或者催收过程命中欺诈标签
2.节点1：欺诈规则判断（图谱因子、历史行为、多头借贷标记）
3.节点2分流：
    - A：确认高欺诈标记 →移交风控/法务，减少普通催收频次
    - B：疑似欺诈 →人工复核队列
    - C：排除欺诈标签 →回到正常催收分案流程
###节点属性
条件节点：引用图谱欺诈因子；输出欺诈标签打至案件。
