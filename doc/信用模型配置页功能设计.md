# 信用模型配置页 · 功能设计

> 本文档定义「零售信贷风控 — 贷前审核 — 信用风控」模块下「信用模型」配置页的产品功能设计。
> 该页面用于配置信用评分的核心计算参数，包括：六大维度权重、各维度下的子指标评分规则、叠加惩罚机制、评分等级映射、自动决策规则。
> 对应代码数据层：`SaaS/src/console/creditReport.ts`（`ScoreComponent` / `CreditDimension` 等类型）。

---

## 一、页面定位与边界

### 1.1 基础定位

| 维度 | 说明 |
|------|------|
| **所属模块** | 零售信贷风控 — 贷前审核 — 信用风控 |
| **页面名称** | 信用模型配置 |
| **页面类型** | 配置型管理页（非列表，表单 + 规则引擎为主） |
| **访问入口** | 左侧菜单「信用风控」→「信用模型」 |
| **操作权限** | 系统管理员、风控策略岗可编辑；风控主管可审批生效；风控专员仅可查看 |
| **数据持久化** | 后端模型配置库，支持版本管理、灰度发布、A/B 测试 |

### 1.2 与信用风控报告的关系

| 维度 | 信用模型（配置端） | 信用风控报告（展示端） |
|------|-------------------|----------------------|
| **关注点** | 评分公式与参数配置 | 单个申请人的评分结果展示 |
| **使用者** | 风控策略岗、系统管理员 | 信审专员、风控主管 |
| **数据流向** | 模型参数 → 评分引擎 → 输出分数 | 接收引擎输出的分数与风险标签 |
| **修改影响** | 修改后新进入件按新模型评分 | 历史报告为快照，不受模型变更影响 |

> **核心原则**：信用模型是「公式」，信用风控报告是「计算结果」。模型配置的每一次调整，只影响调整后新产生的进件评分，不影响历史已生成的报告。

## 二、在贷前审核与贷中监控中的作用

### 2.1 贷前审核中的作用

信用模型是贷前审核「信用风控」环节的**评分计算核心**，直接决定每一笔进件的信用评分与自动审核决策：

1. **评分计算**：将申请人的身份、还款、信用历史、行为、设备、关联六维数据，按模型配置的权重和规则，计算为 0–100 的信用评分。
2. **自动决策分流**：根据评分等级映射，自动判定「通过 / 预警 / 拒绝」，减少人工审核工作量。
3. **风险定价输入**：信用评分作为授信额度、利率定价的输入参数（评分越高，授信额度越高、利率越低）。
4. **策略迭代**：风控策略岗可根据贷后表现（逾期率、坏账率）调整模型参数，优化风控效果。

### 2.2 贷中监控中的作用

信用模型不仅影响贷前审核，也是贷中监控风险评分的基础：

1. **模型调优响应市场变化**：如宏观经济下行期，可调高「还款能力」维度权重；如发现某类设备欺诈增多，可调高「设备安全性」维度权重。
2. **灰度发布与 A/B 测试**：新模型可灰度发布到部分产品或客群，对比新旧模型的 KS 值、AUC 值，验证效果后再全量生效。
3. **回溯分析**：支持将新模型参数回灌历史进件，计算「如果当时用新模型，这批客群的评分分布会如何变化」，辅助策略决策。
4. **监管合规**：模型变更需留痕（变更人、变更时间、变更理由、审批人），满足监管审计要求。

## 四、模型全局信息卡

### 4.1 配置项

| 配置项 | 类型 | 必填 | 默认值 | 说明 |
|--------|------|:----:|--------|------|
| **模型名称** | 文本 | 是 | — | 如「标准信用评分模型 V3.2」 |
| **版本号** | 文本 | 是 | 自动 | 格式 `V{major}.{minor}.{patch}`，保存时自动递增 patch |
| **生效状态** | 单选 | 是 | 草稿 | `草稿 / 已生效 / 已下线`；同一产品同一时间仅一条「已生效」模型 |
| **适用范围** | 单选 | 是 | 全产品 | `全产品 / 指定产品`；指定产品时弹出多选产品列表 |
| **模型描述** | 多行文本 | 否 | — | 说明本模型的适用场景、设计思路 |
| **变更原因** | 多行文本 | 是（生效时） | — | 生效审批时必须填写，记录为什么做本次变更 |
| **总分上限** | 数字 | 是 | 100 | 信用评分总分上限，固定 100 |
| **总分下限** | 数字 | 是 | 0 | 信用评分总分下限，固定 0 |

### 4.2 权重总和校验

六大维度权重之和必须等于 100%，保存时系统自动校验：
- 权重和 = 100% → 允许保存
- 权重和 ≠ 100% → 提示「六大维度权重之和必须为 100%，当前为 X%」

## 五、六大维度配置

### 5.1 左侧维度导航列表

| 维度 | 标识 | 默认权重 | 图标 | 说明 |
|------|------|:--------:|:----:|------|
| **身份真实性** | `identity` | 20% | 🆔 | 公安实名、银行卡四要素、活体检测、运营商实名 |
| **还款能力** | `repayment` | 25% | 💰 | 月收入、负债率、工作稳定性、学历、资产 |
| **信用历史** | `credit_history` | 25% | 📊 | 征信查询、逾期记录、授信记录、多头借贷、账户年龄 |
| **行为稳定性** | `behavior` | 10% | 🚶 | 入网时长、设备使用时长、申请频率、居住/职业稳定性 |
| **设备安全性** | `device` | 10% | 📱 | Root/越狱、模拟器、VPN/代理、设备关联数 |
| **关联风险** | `association` | 10% | 🔗 | 设备/手机号/IP/银行卡关联、团伙关联 |

> 权重可直接在左侧列表中拖动调整（显示为滑块或数字输入框），调整时右侧进度条实时更新占比。

### 5.2 维度基础信息（右侧顶部）

选中某维度后，右侧顶部展示该维度的基础配置：

| 配置项 | 类型 | 必填 | 说明 |
|--------|------|:----:|------|
| **维度名称** | 文本 | 是 | 可自定义，如「身份真实性」可改为「身份核验」 |
| **维度标识** | 文本 | 是（只读） | 系统内部标识，如 `identity` |
| **维度权重** | 数字输入 + 滑块 | 是 | 0%–100%，精确到 0.1% |
| **维度说明** | 多行文本 | 否 | 该维度的评分逻辑说明 |
| **数据源** | 多选 | 是 | 该维度依赖的数据源（人行征信 / 内部库 / 同盾联防 / 运营商等） |
| **维度总分** | 数字 | 是 | 该维度在模型中的满分值（默认 100，即该维度内部按 0–100 打分，再按权重折算到总分） |

### 5.3 子指标评分规则表（核心）

每个维度下包含 N 个子指标，每个子指标配置独立的评分规则。

#### 5.3.1 子指标结构

| 字段 | 类型 | 必填 | 说明 |
|------|------|:----:|------|
| **子指标名称** | 文本 | 是 | 如「人脸比对相似度」「近30天申贷平台数」 |
| **子指标标识** | 文本 | 是 | 系统内部标识，如 `face_similarity`、`plat_30d` |
| **数据字段** | 下拉 | 是 | 绑定到哪个数据源返回字段 |
| **数据类型** | 单选 | 是 | `数值 / 枚举 / 布尔 / 文本` |
| **该指标满分** | 数字 | 是 | 该子指标在维度内的满分值 |
| **该指标权重** | 数字 | 是 | 该子指标在维度内的权重占比（维度内所有子指标权重之和 = 100%） |
| **评分规则** | 规则组 | 是 | 见 5.3.2 |
| **是否启用** | 开关 | 是 | 默认开启 |

#### 5.3.2 评分规则配置

评分规则定义「原始数据值 → 得分」的映射关系。支持三种规则类型：

**① 阈值分段规则（适用于数值型）**

| 条件区间 | 得分 | 说明 |
|---------|------|------|
| ≥ 95 | 100 | 高置信通过 |
| 80 – 94 | 80 | 中置信 |
| 60 – 79 | 50 | 低置信 |
| < 60 | 0 | 拒绝 |

> 区间支持「≥ / > / ≤ / < / 在区间内 / 在区间外」运算符，支持配置任意数量的分段。

**② 枚举映射规则（适用于枚举型）**

| 枚举值 | 得分 | 说明 |
|--------|------|------|
| 正常 | 100 | — |
| 停机 | 50 | — |
| 销号 | 0 | — |
| 未实名 | 0 | — |

**③ 公式计算规则（适用于复杂计算）**

支持配置简单的计算公式，如：
- `score = 100 - (plat_30d * 5)`（申贷平台数越多，得分越低）
- `score = max(0, 100 - debt_ratio * 100)`（负债率越高，得分越低）

> 公式规则需后端支持安全沙箱执行，前端仅做公式语法校验。

#### 5.3.3 以「身份真实性」维度为例的默认子指标

| 子指标 | 数据类型 | 满分 | 权重 | 默认评分规则 |
|--------|---------|:----:|:----:|-------------|
| 公安实名一致性 | 枚举 | 100 | 30% | 一致=100，不一致=0 |
| 银行卡四要素一致性 | 枚举 | 100 | 25% | 一致=100，不一致=0 |
| 人脸比对相似度 | 数值 | 100 | 25% | ≥95=100，≥80=80，<80=0 |
| 活体检测结果 | 枚举 | 100 | 10% | 通过=100，失败=0 |
| 运营商实名一致性 | 枚举 | 100 | 10% | 一致=100，不一致=0 |

#### 5.3.4 以「还款能力」维度为例的默认子指标

| 子指标 | 数据类型 | 满分 | 权重 | 默认评分规则 |
|--------|---------|:----:|:----:|-------------|
| 月收入水平 | 数值 | 100 | 25% | ≥20000=100，≥10000=80，≥5000=60，<5000=30 |
| 负债收入比 | 数值 | 100 | 30% | ≤30%=100，≤50%=70，≤80%=40，>80%=0 |
| 工作稳定性 | 枚举 | 100 | 20% | 正式员工=100，合同工=70，自由职业=40，无业=0 |
| 学历水平 | 枚举 | 100 | 15% | 研究生+=100，本科=80，大专=60，高中=40，其他=20 |
| 资产情况 | 枚举 | 100 | 10% | 有房有车=100，有房=80，有车=60，无=30 |

## 六、惩罚机制配置

惩罚机制是在六大维度基础评分之上，叠加的**额外扣分规则**。用于处理跨维度的严重风险信号，如黑名单命中、失信记录、团伙关联等。

### 6.1 惩罚规则列表

| 配置项 | 类型 | 必填 | 说明 |
|--------|------|:----:|------|
| **惩罚名称** | 文本 | 是 | 如「黑名单命中惩罚」「失信记录惩罚」 |
| **惩罚标识** | 文本 | 是 | 系统内部标识，如 `blacklist_penalty` |
| **触发条件** | 条件组 | 是 | 见 6.2 |
| **惩罚方式** | 单选 | 是 | `固定扣分 / 比例扣分 / 直接置为拒绝阈值` |
| **惩罚值** | 数字 | 是 | 固定扣分：扣 N 分；比例扣分：扣总分 × N%；直接拒绝：无 |
| **惩罚上限** | 数字 | 否 | 该惩罚最多扣多少分（防止多项惩罚叠加导致分数过低） |
| **是否可豁免** | 开关 | 是 | 开启后，信审员可在信用风控报告中对该惩罚进行豁免操作 |
| **豁免审批级别** | 单选 | 否 | `自免（信审员可直接豁免）/ 需审批（需主管审批）/ 不可豁免` |
| **是否启用** | 开关 | 是 | 默认开启 |

### 6.2 触发条件配置

惩罚规则的触发条件支持多条件组合（且 / 或关系）：

| 条件类型 | 说明 | 示例 |
|---------|------|------|
| **数据源结论** | 某数据源返回特定结论 | 同盾联防返回「高风险」 |
| **黑名单命中** | 命中特定黑名单库 | 命中身份证号黑名单 |
| **评分阈值** | 某维度评分低于阈值 | 身份真实性维度评分 < 60 |
| **组合条件** | 多个条件同时满足 | 多头借贷 ≥ 5 家 **且** 负债率 > 80% |

### 6.3 默认惩罚规则

| 惩罚名称 | 触发条件 | 惩罚方式 | 惩罚值 | 是否可豁免 |
|---------|---------|---------|--------|:--------:|
| 黑名单命中 | 命中手机号/身份证/设备黑名单 | 直接置为拒绝阈值 | — | 不可豁免 |
| 失信被执行人 | 命中法院失信被执行人 | 固定扣分 | −30 | 需审批 |
| 团伙欺诈关联 | 同盾联防返回团伙关联 | 固定扣分 | −25 | 需审批 |
| 重度多头借贷 | 近30天申贷平台数 ≥ 10 | 比例扣分 | −20% | 可自免 |
| 高负债率 | 负债收入比 > 100% | 固定扣分 | −20 | 可自免 |
| 设备异常 | 模拟器 / Root / VPN | 固定扣分 | −15 | 可自免 |

> 惩罚规则按**优先级自上而下**匹配，命中即执行，支持配置「命中后是否继续匹配后续惩罚」。

## 七、评分等级与自动决策映射

### 7.1 评分等级划分

信用评分 0–100 分为多个等级，每个等级对应不同的风险等级和自动决策：

| 等级名称 | 评分区间 | 风险等级 | 自动审核决策 | 人工审核 | 说明 |
|---------|:--------:|:--------:|:-----------:|:--------:|------|
| **优秀** | 801–900 | 低 | 通过 | — | 信用良好，自动通过 |
| **良好** | 651–800 | 低 | 通过 | — | 信用良好，自动通过 |
| **一般** | 501–650 | 中 | 预警 | 待审核 | 需人工复核 |
| **较差** | 301–500 | 高 | 拒绝 | — | 自动拒绝 |
| **极差** | 0–300 | 高 | 拒绝 | — | 自动拒绝 |

> 注：实际评分区间为 0–100，此处 801–900 等是为了兼容外部评分体系（如芝麻分 350–950）。本 SaaS 内部统一使用 0–100 分制，如需对接外部评分，在数据源映射层做转换。

### 7.2 等级映射配置

| 配置项 | 类型 | 必填 | 说明 |
|--------|------|:----:|------|
| **等级名称** | 文本 | 是 | 如「优秀」「良好」 |
| **评分下限** | 数字 | 是 | 该等级的最低分数（含） |
| **评分上限** | 数字 | 是 | 该等级的最高分数（含） |
| **风险等级** | 单选 | 是 | `低 / 中 / 高` |
| **自动审核决策** | 单选 | 是 | `通过 / 预警 / 拒绝` |
| **是否需人工复核** | 开关 | 是 | 开启后，该等级的进件必须经人工审核 |
| **授信额度比例** | 数字 | 否 | 该等级可获得的授信额度占申请额度的比例（如 100% = 全额授信） |
| **等级颜色** | 颜色选择 | 是 | 在报告中该等级显示的颜色 |

### 7.3 默认等级映射

| 评分区间 | 等级 | 风险等级 | 自动决策 | 授信额度比例 | 颜色 |
|:--------:|:----:|:--------:|:--------:|:-----------:|:----:|
| 75–100 | A | 低 | 通过 | 100% | 🟢 绿 |
| 60–74 | B | 中 | 预警 | 70% | 🟡 黄 |
| 45–59 | C | 高 | 拒绝 | 0% | 🟠 橙 |
| 0–44 | D | 高 | 拒绝 | 0% | 🔴 红 |

> 系统预置上述默认映射，用户可调整区间边界、等级名称、授信额度比例。

## 八、模型版本管理与变更日志

### 8.1 版本管理

| 操作 | 说明 |
|------|------|
| **保存草稿** | 编辑后保存为草稿状态，不影响生产环境 |
| **生效审批** | 风控主管点击「生效」时，弹出确认框要求填写「生效原因」和「预计影响客群」，提交后进入审批流程 |
| **灰度发布** | 支持选择灰度范围：`按产品` / `按客群` / `按流量比例`（如 10% 流量使用新模型） |
| **下线** | 将已生效模型下线，下线后新进入件使用上一版生效模型 |
| **回滚** | 将当前模型恢复到指定历史版本，恢复后版本号自动递增 |
| **对比** | 选择两个版本，系统高亮展示差异项（权重变化、规则增删、阈值调整） |

### 8.2 变更日志

| 字段 | 说明 |
|------|------|
| **版本号** | 模型版本 |
| **操作类型** | `创建 / 编辑 / 生效 / 灰度 / 下线 / 回滚` |
| **操作人** | 系统用户 |
| **操作时间** | 精确到秒 |
| **变更摘要** | 自动生成的变更说明（如「身份真实性权重：20% → 25%；新增惩罚规则：设备异常」） |
| **审批人** | 生效审批时的审批人 |
| **审批意见** | 审批人填写的意见 |
| **操作** | `查看详情 / 回滚到此版本 / 对比上一版本` |

## 九、与信用风控报告的衔接

信用模型配置页修改的参数，直接影响「信用风控报告详情页」中以下区域的展示：

| 报告详情区域 | 受影响的配置项 |
|-------------|--------------|
| **领衔区 1 · 信用评分总览** | 六大维度权重 → 六维评分条；等级映射 → 信用等级（A/B/C/D）与颜色 |
| **领衔区 2 · 结论与终审操作** | 等级映射 → 自动审核决策（通过/预警/拒绝）；授信额度比例 → 建议授信额度 |
| **二~六、各维度详情** | 各维度的子指标评分规则 → 维度内各子指标的得分展示 |
| **风险因子分析** | 维度权重 → 六维权重饼图/条；惩罚机制 → 风险标签（如「黑名单命中」「重度多头」） |
| **风控决策建议** | 等级映射 → 系统建议文案（如「信用良好，违约风险较低」） |

> 模型配置生效后，新进入件的信用评分按新模型计算；历史已生成的信用风控报告不受影响（报告为快照）。

## 十一、数据模型（TypeScript 类型）

```typescript
// 信用模型整体结构
interface CreditModel {
  id: string;                    // 模型唯一 ID
  name: string;                  // 模型名称
  version: string;               // 版本号
  status: 'draft' | 'active' | 'inactive';  // 状态
  scope: 'all' | 'specific';     // 适用范围
  products?: string[];           // 指定产品列表
  description?: string;          // 模型描述
  changeReason?: string;         // 变更原因
  totalScoreMin: number;         // 总分下限（默认 0）
  totalScoreMax: number;         // 总分上限（默认 100）
  dimensions: CreditDimension[]; // 六大维度配置
  penalties: PenaltyRule[];      // 惩罚机制
  gradeMapping: GradeMapping[];  // 评分等级映射
  changeLogs: ChangeLog[];       // 变更日志
  createdAt: string;
  updatedAt: string;
  updatedBy: string;
}

// 信用维度
interface CreditDimension {
  id: string;                    // 维度标识，如 identity
  name: string;                  // 维度名称
  weight: number;                // 维度权重（0–100，%）
  description?: string;          // 维度说明
  dataSources: string[];         // 依赖的数据源
  maxScore: number;              // 维度内满分（默认 100）
  subIndicators: SubIndicator[]; // 子指标列表
  enabled: boolean;              // 是否启用
}

// 子指标
interface SubIndicator {
  id: string;                    // 子指标标识
  name: string;                  // 子指标名称
  dataField: string;             // 绑定的数据字段
  dataType: 'number' | 'enum' | 'boolean' | 'string';
  maxScore: number;              // 该指标满分
  weight: number;                // 该指标在维度内的权重（%）
  scoringRules: ScoringRule[];   // 评分规则列表
  enabled: boolean;
}

// 评分规则（三种类型）
type ScoringRule =
  | { type: 'threshold'; segments: ThresholdSegment[] }
  | { type: 'enum'; mappings: EnumMapping[] }
  | { type: 'formula'; expression: string };

interface ThresholdSegment {
  operator: '>=' | '>' | '<=' | '<' | 'between' | 'outside';
  value: number | [number, number];  // 单值或区间
  score: number;                   // 该区间对应的得分
  label?: string;                  // 区间标签，如"高置信通过"
}

interface EnumMapping {
  value: string;                   // 枚举值
  score: number;                   // 对应得分
  label?: string;
}

// 惩罚规则
interface PenaltyRule {
  id: string;
  name: string;
  triggerConditions: TriggerCondition[];  // 触发条件
  logic: 'and' | 'or';              // 条件组合逻辑
  penaltyType: 'fixed' | 'ratio' | 'reject';  // 惩罚方式
  penaltyValue?: number;            // 惩罚值（固定扣分值或比例）
  maxPenalty?: number;              // 惩罚上限
  exemptible: boolean;              // 是否可豁免
  exemptLevel?: 'self' | 'approval' | 'none';  // 豁免级别
  enabled: boolean;
}

interface TriggerCondition {
  type: 'data_source' | 'blacklist' | 'score_threshold' | 'composite';
  config: Record<string, any>;
}

// 评分等级映射
interface GradeMapping {
  grade: string;                   // 等级名称，如 A/B/C/D
  label: string;                   // 友好名称，如 优秀/良好/一般/较差
  minScore: number;                // 评分下限（含）
  maxScore: number;                // 评分上限（含）
  riskLevel: 'low' | 'medium' | 'high';  // 风险等级
  autoDecision: 'pass' | 'warning' | 'reject';  // 自动审核决策
  needManualReview: boolean;       // 是否需人工复核
  creditLimitRatio?: number;       // 授信额度比例（%）
  color: string;                   // 等级颜色
}

// 变更日志
interface ChangeLog {
  version: string;
  action: 'create' | 'edit' | 'activate' | 'gray' | 'deactivate' | 'rollback';
  operator: string;
  timestamp: string;
  summary: string;
  approver?: string;
  approvalComment?: string;
}
```

## 十三、验收要点（开发 checklist）

- [ ] 模型全局信息：名称、版本、状态、适用范围、描述可配置
- [ ] 六大维度权重：可配置，且权重之和必须等于 100%

- [ ] 与报告衔接：模型配置修改后，新进入件的信用评分按新模型计算
- [ ] 权限控制：不同角色拥有不同的查看/编辑/生效/回滚权限
- [ ] 灰度发布（未来扩展）：支持按产品/客群/流量比例灰度生效
