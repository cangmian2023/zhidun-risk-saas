# 全维搜索页面 1:1 复刻转换手册

## 一、使用的资料文件

资料全部来自 `record/qixin/` 目录，是 Chrome「另存为完整网页」保存的快照：

| 文件 | 作用 | 大小 |
|------|------|------|
| `营销 - 全维搜索` | 企业搜索主页面 **内容**（无后缀，DOM dump） | 2.3MB |
| `营销 - 全维搜索.html` | 企业搜索主页面 **CSS 来源**（含 `_files` 目录） | 2.8MB |
| `营销 - 全维搜索 - 人员.html` | 人员搜索 **内容+CSS**（含 `_files` 目录） | 209KB |
| `营销 - 全维搜索 - 商机.html` | 商机搜索 **内容+CSS**（含 `_files` 目录） | 255KB |
| `营销 - 全维搜索 - 风险.html` | 风险搜索 **内容+CSS**（含 `_files` 目录） | 176KB |
| `营销 - 全维搜索 - 研报.html` | 研报搜索 **内容+CSS**（含 `_files` 目录） | 156KB |

> **关键区分**：
> - **无后缀文件** = Vue 渲染后的 DOM dump，纯 HTML 标签，**含全部内容数据**（表格、文字、SVG 图），但不含 `<style>`/`<link>`
> - **.html 文件** = 完整网页，**含 CSS 来源**（`<link rel="stylesheet">` 引用 `_files` 目录下的 vendor.css + index.css + chunk css）
> - **`_files` 目录** = .html 的配套资源文件夹，包含所有 CSS/图片/字体文件

## 二、整体转换流程（6 步）

### 第 1 步：删除旧版

删除预生成的旧产物：
```bash
rm -rf src/console/qixinData
```

旧版是把 qixin 快照预生成 TypeScript 文件（`person-basic.ts` 等），构建时打包进去。
新版改为**运行时直接 fetch 原始 HTML 文件**，不预生成。

---

### 第 2 步：创建运行时加载器（`qixinRuntime.ts`）

新建 `src/console/qixinRuntime.ts`，封装两种加载模式：

#### 模式 A：`loadQixinPage(srcName, htmlName)`
用于**有同名无后缀文件**的情况（如企业搜索）。

```typescript
// 1. fetch 无后缀文件 = HTML 内容主源
const html = await fetch('/qixin-raw/' + encodeURIComponent('营销 - 全维搜索'));

// 2. fetch .html 文件 = 提取 CSS
const pageHtml = await fetch('/qixin-raw/' + encodeURIComponent('营销 - 全维搜索.html'));
const css = extractCss(pageHtml);  // 见下文 CSS 提取管线

// 3. 剥离 <script>（防止 Vue 挂载清空 SSR 内容）
html = html.replace(/<script\b[\s\S]*?<\/script>/gi, '');

// 4. 链接重写（原站路径 → 本地 hash）
html = rewriteLinks(html);

return { html, css };
```

#### 模式 B：`loadQixinPageFromHtml(htmlName)`
用于**只有 .html 文件**的情况（如人员/商机/风险/研报搜索）。

```typescript
// 1. fetch .html 文件
const pageHtml = await fetch('/qixin-raw/' + encodeURIComponent('营销 - 全维搜索 - 人员.html'));

// 2. 提取内容：优先找 <div id="content">，找不到则取整个 <body>
const html = extractBody(pageHtml);

// 3. 提取 CSS（同模式 A）
const css = extractCss(pageHtml);

// 4. 剥离 script + 链接重写
html = html.replace(/<script\b[\s\S]*?<\/script>/gi, '');
html = rewriteLinks(html);

return { html, css };
```

> **为什么模式 B 要提取 `#content`**：
> 人员/商机/风险/研报的 .html 文件是完整网页，包含 `<header>`、`<sidebar>`、`<footer>` 等外壳。
> 这些外壳在 SaaS 系统中是多余的（系统已经有自己的顶部导航和左侧菜单）。
> 原始页面把功能区放在 `<div id="content">` 内，所以提取 `#content` 即可去掉外壳。

---

### 第 3 步：CSS 提取管线（核心）

`.html` 文件本身不直接含 CSS，它通过 `<link>` 引用 `_files` 目录下的 CSS 文件。
需要把分散的 CSS 合并成一个大字符串：

```
.html 文件
  ├── <link href="./xxx_files/vendor.css">
  ├── <link href="./xxx_files/index.css">
  ├── <link href="./xxx_files/chunk-1.css">
  ├── <link href="./xxx_files/chunk-2.css">
  └── <style>...</style>（内联样式）
```

提取流程：
1. **解析 .html** → 找到所有 `<link rel="stylesheet">`
2. **逐个 fetch CSS 文件**
3. **递归内联 `@import`**（CSS 里可能 `@import './index-partial1.css'`，需要再 fetch）
4. **重写 `url()` 路径**（相对路径 `./images/logo.png` → 绝对路径 `/qixin-raw/xxx_files/images/logo.png`）
5. **收集 `<style>` 标签**
6. **合并成一个大 CSS 字符串**

这样 Shadow DOM 内只需要一个 `<style>` 标签，就能包含全部样式。

---

### 第 4 步：链接重写

原始 HTML 里的链接指向 qixin 原站：
```html
<a href="/name/info?pid=xxx">基本信息</a>
<a href="/company/info?eid=xxx">企业档案</a>
```

需要重写成：
- **个人档案路径** → 本地 hash：`/name/info` → `#basic`，`/name/lawsuit` → `#risk`
- **企业档案路径** → 本地 hash：`/company/info` → `#basic`，`/company/history` → `#history`
- **未知路径** → 外部完整 URL + `target="_blank"`：`/home` → `https://b.qixin.com/home`

这样点击链接不会跳到 qixin 原站，而是在 SaaS 系统内切换 Tab 或新窗口打开。

---

```typescript

  // 4. 切换 hash 时调用对应 loader 加载新页面
```

### 第 6 步：Shadow DOM 注入

```typescript
const root = el.attachShadow({ mode: 'open' });
root.innerHTML = '';

const style = document.createElement('style');
style.textContent = css;  // 1MB+ 合并后的 CSS

const body = document.createElement('div');
body.innerHTML = html;    // 提取后的 HTML 内容

root.append(style, body);
```

**为什么用 Shadow DOM**：
- qixin 的 CSS 类名（`.el-tabs__item`、`.btn-primary` 等）可能与 SaaS 项目的 CSS 冲突
- Shadow DOM 内部样式与外部宿主完全隔离
- qixin 的样式只影响 Shadow DOM 内部，不会污染整个页面

## 三、两个模式的选择标准

| 场景 | 使用模式 | 原因 |
|------|---------|------|
| 有同名无后缀文件 + 有 .html | `loadQixinPage(src, html)` | 无后缀 = 纯内容 DOM dump，.html = CSS 来源，各取所长 |
| 只有 .html（无同名无后缀） | `loadQixinPageFromHtml(html)` | 从 .html 提取 body/#content 作为内容，同时提取 CSS |
| 只有无后缀（无 .html） | 无法直接复刻 | 无 CSS 来源，内容会显示为纯文本堆叠 |

## 四、`/qixin-raw` 是什么？

`vite.config.js` 里配置了一个 Vite 插件，把 `record/qixin/` 目录原样映射到 `/qixin-raw/` URL：

```
浏览器请求 /qixin-raw/营销 - 全维搜索.html
         ↓
Vite 插件读取 record/qixin/营销 - 全维搜索.html
         ↓
按真实 MIME 返回（.html → text/html, .css → text/css, .png → image/png）
```

这样前端可以用 `fetch('/qixin-raw/...')` 直接读取原始文件。

## 五、常见问题

### Q1：为什么人员/商机/风险/研报页面有结构问题？
因为这些 .html 文件是**完整网页**，包含 header、sidebar、footer 等外壳。
解决：从 .html 提取 `<div id="content">` 内容区，去掉外壳。

### Q2：为什么企业页面没有结构问题？
因为企业页面用的是**无后缀文件**（DOM dump），本身就只含内容区，不含外壳。

### Q3：为什么点击 Tab 不能切换？
因为原始页面是 Vue SPA，Tab 切换由 Vue 的 JS 控制。剥离 `<script>` 后 JS 失效。
解决：在 Shadow DOM 注入后，给 `el-tabs__item` 元素手动绑定 `click` 事件，触发 `window.location.hash` 切换。

### Q4：为什么图片/字体显示不出来？
因为 CSS 里的 `url()` 是相对路径（`./xxx_files/images/logo.png`），需要重写成绝对路径（`/qixin-raw/xxx_files/images/logo.png`）。
CSS 提取管线会自动做这个重写。
