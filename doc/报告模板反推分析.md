> 目标：用四个已确定内容的报告（信息核验 / 信用风控 / 欺诈方案4 / 决策报告）**反推**「报告模板」应如何配置，确认是否「全部能用模板配出来」。

## 三、跨报告共性能力缺口（需扩展模板模型）

1. **图表类型不足**：`DisplayComponent` 仅 `大数字/环形图/进度条/仪表盘`。缺 **折线/趋势图、雷达图、柱状图**。→ 信用趋势、雷达图不可配。
2. **图谱/关系图容器缺失**：设备关联图谱、团伙关联图谱无对应数据结构与渲染容器。
3. **卡片网格 + 点击锚点联动**：原子卡/疑点卡/因子卡的「并列多卡 + 点击跳转定位」无法表达（仅字段显隐/标签）。
4. **跨字段计算 / 表达式**：`信用值=满分−风险值`、`决策评分=0.3×核验+0.4×信用+0.3×欺诈`、`命中占比%` 等需在模板引入计算表达式/聚合定义。
5. **状态机操作按钮**：各报告独立 `workStatus`/`OPERATIONS` 状态机（信息核验 / 欺诈 10 态等）未与 `businessFlow` 对齐；模板只有 通过/拒绝/转人工 三态 + 人工节点。
6. **聚合/汇总卡 & 跨报告跳转**：决策「三大报告汇总」、各报告「查看完整报告 →」跳转链接无对应。
7. **决策报告模板模型不统一**：见 §2.4。

## 六、最大结构性 gap：模板与详情页解耦

四个真实详情页主体全部硬编码独立实现：
- 原唯一在正文引用模板的是**已删除的 `CreditReportDetail`**（其审批弹窗用 `getAuditFlow`）。删除后，**四个详情页正文均不消费 `reportTemplateData` 做渲染**。
- 但**审批弹窗层已打通**：`ApprovalModal` + `getAuditFlow` 被 `VerifyOps` / `FraudScheme4Ops` / `CreditKimiOps` 引用，弹窗内容由模板 `businessFlow` 驱动（四报告一致）。即「模板 → 审批弹窗」已闭环，「模板 → 报告正文渲染」仍未闭环。
- 配置 UI 的「预览」(`ReportTemplatePreview.tsx`) 是另一套通用清单式渲染，遍历 `tpl.sections` 但样例写死在 `PREVIEW_SAMPLE`，未复刻真实图表的图谱/交互。

**含义**：即便把模板配置到 100% 吻合报告结构，**详情页仍不会按模板渲染**。「用模板配出四个报告」的真正闭环，需要：
1. 扩展模型覆盖 §三 的缺口；
2. 把四个详情页改为**消费** `ReportTemplate.sections` + `scoreDisplay` + `businessFlow` + 上述新类型。

这是比「配置 4 个模板」大得多的工程，建议作为独立阶段。

## 八、用户新增要求：通用评分模型（区块总分 × 区块权重 = 报告总分）

> 来源：用户 2026-07-29 二次反馈。这是「报告模板」应支持的**评分计算内核**，反推模板配置时必须纳入。

### 8.1 规则（用户原话转述）
1. 报告的**每一项**都应有一个**小得分**（item score）。
2. 一个**区块（section / panel）**应有一个**区块总分**（section total = 该区块内各小得分按权重聚合）。
3. 每个区块应有一个**权重**（section weight）。
4. **报告总分 = Σ(区块总分 × 区块权重)**（所有权重累加应归一，整体即加权总分）。

### 8.2 与现有报告的对照
| 报告 | 是否已具备该模型 | 现状 |
|---|---|---|
| 信用风控（真实页 CreditKimiDetail） | ✅ 天然契合 | 每个维度（区块）有 `score`（区块总分）、内部 `items` 有 `score`+`weight`、`加权得分=得分×权重`；顶部总览展示「六维加权分布」。`creditScore`(300-900) 即六维加权汇总。是四报告里唯一已落地的范本。 |
| 信息核验 | ⚠️ 部分 | 顶部有「异常值/信用值」总分，但区块（基本资料/单项核验/交叉融合）无独立小得分与权重。需补。 |
| 欺诈方案4 | ⚠️ 部分 | 顶部有欺诈分，但各 RuleTable 区（身份/信息/设备/行为/团伙）无统一「区块总分×权重」聚合。需补。 |
| 决策报告 | ❌ 无 | 仅「三大报告评分汇总」，无区块级小得分/权重；跨报告加权（0.3×核验+0.4×信用+0.3×欺诈）属跨字段计算（§三.4），尚未建模。 |

### 8.3 对模板模型的改造要求
- `ReportSection` 需新增 `scoreWeight`（区块权重，0–1 或百分比）与 `sectionScoreExpr`（区块总分计算：如 `sum(item.score × item.weight)`）。
- 区块内条目需支持 `itemScore`（小得分）与 `itemWeight`（条目权重）。
- 报告级需新增 `reportScoreExpr`：`Σ(sectionScore × sectionWeight)`，作为模板可声明的「报告总分算法」。
- 该模型与 §三.4「跨字段计算」、§四「CalcExpr / AggRule」扩展高度重合——可合并为同一套「评分 / 聚合表达式引擎」。

### 8.4 落地建议
优先以信用风控为范本，把该评分内核抽象进模板；再反向补到信息核验 / 欺诈 / 决策三报告，使四报告共享同一套「区块–条目–权重–总分」模型。属模型扩展阶段任务（接 §四）。
