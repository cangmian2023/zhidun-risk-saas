# 模型评分全景说明（智察分 · 智信分 · 智融分）

> 写给不熟悉风控模型的同学：把三个模型**从原始数据到最终得分**的全过程讲明白，
> 并写清每个模型的用途、输入、输出、算法、预警区间、标签和处置。
> 本文档与页面「得分详情」（单客详情 → 模型评分）各 Tab 内容一一对应，可对照看。

---

## 一、先说三件最基本的事（必读）

### 1.1 什么是"模型评分"

模型评分就是：**把客户的各类数据喂给一个数学模型，让它算出一个分数，用分数表示这个客户的风险高低**。

类比：银行柜员看人下菜碟——看征信、看收入、看有没有案底，然后心里打个分。模型就是把这个"心里打分"变成标准化、可追溯的机器打分。

### 1.2 三个模型各管什么

| | 智察分 | 智信分 | 智融分 |
|---|---|---|---|
| 管什么 | **反欺诈**：这人是不是骗子 | **信用**：这人会不会还不起钱 | **综合**：整体能不能给额度 |
| 分数范围 | 0 – 100 分（欺诈分） | 300 – 900 分（信用分） | 300 – 900 分（综合分） |
| 分数方向 | **越高越危险** | **越高越好** | **越高越好** |
| 算法 | XGBoost + 规则引擎融合 | LightGBM 评分卡 | 逻辑回归融合模型 |

> ⚠️ **最容易看反的两点**：
> 1. **智察分是反着看的**——78 分 = 高风险（有欺诈嫌疑），20 分 = 安全。而智信分 78 分 = 很差。同一个数字，方向完全相反，页面用颜色区分（红 = 危险方向）。
> 2. **标度不同**——智察分满分 100，智信/智融满分 900。看到"688"和"78"不要直接比大小，它们不是一回事。

### 1.3 数据是怎么一步步变成得分的（通用流水线）

```
原始数据 ──▶ 数据治理 ──▶ 特征工程 ──▶ 模型计算 ──▶ 模型得分
(一堆杂数据)  (清洗整理)   (提炼有用信号)  (数学计算)    (最终分数)
```

每一步打个比方（以"看一个人是不是骗子"为例）：

| 环节 | 干什么 | 类比 |
|---|---|---|
| **原始数据** | 把设备指纹、征信、多头借贷、黑名单等系统里的原始记录拉出来 | 把"这人名下所有档案"搬上桌 |
| **数据治理** | 去重、补缺失、按时间窗切分（近 7 天 / 30 天 / 90 天）、统一格式 | 把档案里重复的、缺页的整理干净 |
| **特征工程** | 从整理好的数据里提炼出"能区分风险高低"的指标，如"近 30 天申请了几家贷款" | 从档案里挑出 36 个关键判断点 |
| **模型计算** | 把特征值喂给算法（XGBoost / LightGBM / 逻辑回归），算出风险概率或分数 | 资深风控员综合 36 个判断点拍板 |
| **模型得分** | 输出最终分数，并套用阈值区间给出等级和处置建议 | 拍板结论：高分（危险）→ 拒绝 / 复核 |

## 二、智察分（反欺诈）详解

### 2.1 用途

**识别欺诈风险**：判断这个申请人是真实客户还是骗子（团伙申贷、设备造假、黑产关联等）。
用在贷前准入拦截，也用在贷中异常识别（如 8 月 4 日负债激增后重评，欺诈分从 74 升到 78）。

### 2.2 输入：用了哪些原始数据（含本客模拟数据）

| 数据 | 本客（张*明）模拟取值 |
|---|---|
| 设备指纹 | DEV-A3F8-9C21，近 30 天关联 3 台设备，模拟器特征置信度 0.92 |
| 申请信息 | 2026-08-08 10:30 申请，渠道 APP，IP 202.xx.xx.16（异地） |
| 多头借贷 | 近 30 天申贷 7 笔，同时在贷 5 家平台 |
| 黑灰名单 | 命中外部灰名单 ID#88231（2025-11 疑似组团申贷） |
| 行为日志 | 近 30 天活跃 18 天，登录设备 2 台 |

### 2.3 数据治理（对原始数据做了什么）

- **实体去重**：同设备 3 个账号合并成 1 个实体（防止一人多号刷量）
- **时间窗切分**：申请行为按 7 / 30 / 90 天窗口聚合
- **缺失填充**：IP 归属缺失用高频值补
- **异常标记**：设备环境风险 ≥0.8 标记为"高风险环境"

### 2.4 特征工程（提炼出的判断指标，共 36 个）

| 关键特征 | 含义 | 全局权重 | 本客状态 |
|---|---|---|---|
| 多头聚集度 | 近 30 天申贷机构数 | 28% | 🔴 触发（7 家，阈值 ≥5） |
| 设备聚集 | 同设备关联账号数 | 24% | 🟡 关注（3 个，阈值 ≥5） |
| 申请频次 | 近 30 天申请次数 | 21% | 🔴 触发 |
| 黑产特征 | 黑灰名单命中 | 16% | 🔴 触发 |
| 同设备关联 | 关联设备风险 | 12% | 🟡 关注 |
| IP/定位异常 | 异地 / 代理 IP | 10% | 🟢 正常 |

> 🔴 触发 = 这项数据踩线，命中规则预警；🟡 关注 = 接近阈值待观察；🟢 正常 = 正常参与评分。

### 2.5 算法

**XGBoost + 规则引擎融合**：用 2019–2025 年历史欺诈样本训练 XGBoost 模型输出欺诈概率，
再叠加**专家硬规则**（命中名单、模拟器等一票否决）和**人工复核**干预，形成最终欺诈分。

### 2.6 输出与得分

输出 0–100 欺诈分。本客得分 **78 分 → 高风险**，决策建议：**拒绝 / 转人工复核 / 冻结止付**。

### 2.7 预警区间 → 标签 → 处置（完整映射）

| 分数区间 | 等级标签 | 含义 | 建议处置 | 触发流程 |
|---|---|---|---|---|
| 70 – 100 | 🔴 高风险 | 欺诈特征显著 | 拒绝 / 转人工复核 / 冻结止付 | 冻结 `f-alert-freeze` |
| 40 – 69 | 🟡 中风险 | 存在部分风险信号 | 人工复核 / 加强监测 | 观察 `f-alert-watch` |
| 0 – 39 | 🟢 低风险 | 无明显欺诈特征 | 通过（继续评估） | — |

## 三、智信分（信用）详解

### 3.1 用途

**评估违约风险**：判断这个客户将来还不还得起钱。用于授信准入、额度核定和定价（利率）。
本客信用分从 3 月的 715 一路降到 8 月的 688（B 档边缘 → C 档），说明信用状况在恶化。

### 3.2 输入：原始数据（含本客模拟数据）

| 数据 | 本客模拟取值 |
|---|---|
| 人行征信 | 信贷账户 12 个，近 6 月查询 8 次 |
| 还款记录 | M3+ 逾期 1 次（2024-09 某银行信用卡逾期 95 天） |
| 负债结构 | 月还款 ¥10,440，月收入 ¥18,000 |
| 收入流水 | 近 12 月连续 14 月入账，月均 ¥18,000（代发工资） |
| 申请信息 | 制造业在职 4 年，社保连续 36 个月 |

### 3.3 数据治理

- **征信标准化**：逾期天数映射成 M1 / M2 / M3+ 等级（M3+ = 逾期超 90 天，最严重）
- **负债比计算**：月还款 ÷ 月收入 = 58%（阈值 70%）
- **收入核验**：代发工资流水与申报收入交叉验证
- **账户去重**：同机构多账户合并

### 3.4 特征工程（42 个信用特征）

| 关键特征 | 含义 | 全局权重 | 本客状态 |
|---|---|---|---|
| 历史还款 | M3+ 逾期次数 / 最长逾期天数 | 28% | 🔴 触发（M3+ 1 次） |
| 负债结构 | 负债收入比 | 22% | 🟡 关注（58%，阈值 70%） |
| 收入稳定 | 连续入账月数 / 收入波动 | 20% | 🟢 正常（14 个月） |
| 征信查询 | 近 6 月贷款审批查询次数 | 14% | 🟢 正常（8 次） |
| 职业属性 | 职业 / 司龄 / 社保连续性 | 9% | 🟢 正常（在职 4 年） |
| 年龄学历 | 人口属性 | 7% | 🟢 正常 |

### 3.5 算法

**LightGBM 评分卡**：信用领域最经典的建模方式。
连续变量做 WOE 分箱（每个区间算风险权重），各分箱得分累加后映射到 300–900，
再经 Platt Scaling 校准输出违约概率（本客 14.2%）。

### 3.6 输出与得分

输出 300–900 信用分。本客 **688 分 → C · 一般**（580-659 是 C 档，688 已在 B 档边缘但历史逾期拖累明显）。

### 3.7 预警区间 → 标签 → 处置（完整映射）

| 分数区间 | 等级标签 | 含义 | 建议处置 | 触发流程 |
|---|---|---|---|---|
| 780 – 900 | 🟢 A · 优质 | 违约概率低 | 准入（标准额度） | — |
| 660 – 779 | 🟢 B · 良好 | 违约概率较低 | 准入（审慎授信） | — |
| 580 – 659 | 🟡 C · 一般 | 违约概率中等 | 降额 / 加强监测 | 降额 `f-alert-limit` |
| 300 – 579 | 🔴 D · 较差 | 违约概率高 | 拒绝 / 冻结 | 冻结 `f-alert-freeze` |

## 四、智融分（综合）详解

### 4.1 用途

**综合评估**：把"欺诈风险 + 信用风险 + 客户价值 + 资产实力"四件事捏在一起，输出一个综合分，
用于**综合授信与额度核定**（比如贷中降额时，看综合分决定降多少）。

### 4.2 输入：原始数据（含本客模拟数据）

| 数据 | 本客模拟取值 |
|---|---|
| 引用智信分 | 688（信用分，代表"违约维度"） |
| 引用智察分 | 78（欺诈分，代表"欺诈维度"） |
| 行为数据 | 近 30 天活跃 18 天，偏好消费分期 / 现金分期 |
| 资产画像 | 自有住房（按揭中），理财持仓 ¥80,000 |

> 注意：智融分**不自己看原始数据**，它直接"引用"智信分和智察分的结论，再补价值、资产两个自有维度。

### 4.3 数据治理

- **分数归一化**：把 300–900 和 0–100 两种标度统一换算成 0–1，才能做加减法
- **维度加权**：违约 0.34 · 欺诈 0.28 · 价值 0.24 · 资产 0.14（权重合计 1）
- **缺失处理**：资产维度缺失按中位值填充

### 4.4 特征工程（4 大维度）

| 维度 | 含义 | 全局权重 | 本客状态 |
|---|---|---|---|
| 违约维度 | 智信分转换 | 34% | 🟡 关注（688） |
| 欺诈维度 | 智察分转换 | 28% | 🔴 触发（78） |
| 价值维度 | 借贷兴趣 / 活跃度 | 24% | 🟢 正常（18 天） |
| 资产维度 | 房产 / 金融资产 | 14% | 🟢 正常 |

### 4.5 算法

**逻辑回归融合模型**：智信分与智察分归一化后按 0.55 / 0.45 加权，叠加价值、资产自有特征
及交互项（如"欺诈分高 + 价值分高"会额外下调），逻辑回归输出综合分，人工复核后定分。

### 4.6 输出与得分

输出 300–900 综合分。本客 **660 分 → C · 一般**，决策建议：**降额 / 加强监测**。

### 4.7 预警区间 → 标签 → 处置（完整映射）

| 分数区间 | 等级标签 | 含义 | 建议处置 | 触发流程 |
|---|---|---|---|---|
| 780 – 900 | 🟢 A · 优质 | 综合风险低、价值高 | 准入（标准额度） | — |
| 660 – 779 | 🟢 B · 良好 | 综合表现良好 | 准入（审慎授信） | — |
| 580 – 659 | 🟡 C · 一般 | 综合表现一般 | 降额 / 加强监测 | 降额 `f-alert-limit` |
| 300 – 579 | 🔴 D · 较差 | 综合风险高 | 拒绝 / 冻结 | 冻结 `f-alert-freeze` |

## 五、三个模型之间到底是什么关系

```
┌──────────┐      ┌──────────┐
│ 原始数据  │───▶ │ 智察分    │──┐
│(多头/设备/ │      │ (欺诈 0-100)│  │
│ 名单/行为) │      └──────────┘  │ 引用
└──────────┘                     ▼
┌──────────┐      ┌──────────┐  ┌──────────┐
│ 原始数据  │───▶ │ 智信分    │─▶│ 智融分    │
│(征信/负债/ │      │ (信用 300-900)│  │ (综合 300-900)│
│ 流水/还款) │      └──────────┘  └──────────┘
└──────────┘                     ▲
┌──────────┐      ┌──────────┐  │ 自有维度
│ 行为/资产 │───▶ │ 价值/资产 │──┘ (价值+资产)
└──────────┘      └──────────┘
```

**一句话总结**：智察分看"是不是骗子"，智信分看"还不还得起"，智融分把两者加上客户价值、资产，揉成"能不能给额度"的综合判断。

### 与"贷中监控"的关系（重要）

贷中监控是**放款之后的持续盯防**，它和模型分是一条因果链：

```
预警事件触发（负债激增 / 多头借贷 / 行为异常）
        │
        ▼
贷中重评（重新跑智察 / 智信 / 智融）
        │
        ▼
分数变化（如智察分 74 → 78，跨过 70 高风险线）
        │
        ▼
驱动处置（冻结 / 降额 / 观察，进入业务流程 f-alert-*）
```

- **分数是"状态"**：反映客户当前风险多高
- **预警 / 处置是"动作"**：预警负责喊"出事了"，处置负责"怎么办"

页面上对应的两块：**预警与处置 Tab**（分值阈值预警 + 规则命中预警 + 处置流程进度）、**操作日志**（数据变动 → 得分影响的时间线）。

### 模型用不用"关系图谱"？（常见疑问）

**结论：三个模型目前都没有用完整的关系图谱。**

- **模型输入特征里没有图谱特征**：智察分（多头聚集 / 设备聚集 / 申请频次 / 黑产特征 / 同设备关联 / IP 异常）、智信分（还款 / 负债 / 收入 / 查询 / 职业）、智融分（违约 / 欺诈 / 价值 / 资产）——里面**没有"担保人、联系人、共债人、关联企业、资金中介"这类社会关系网络特征**。
- **唯一沾边**：智察分的"同设备关联账号"特征，数据源标注为"账号关系图谱"——但那是**设备维度的浅关联**（一台设备挂多个账号），不是客户的社会关系网。
- **现状是"数据有、页面有、模型没有"**：系统里有完整的关联图谱数据（法人 / 担保 / 设备 / 联系人 / 共债人节点，带风险等级与预警数），单客详情页也有可视化，但**只用于展示，没有喂给模型**。

**专业上图谱该用在哪个模型？** 最该喂给**智察分（反欺诈）**，因为欺诈天然呈团伙化。可选特征：
- **团伙聚集度**：关联节点数、同担保人 / 同联系人 / 同设备 / 同 IP 的聚集数量
- **风险传导**：二度关联内是否存在 M3+ 逾期 / 欺诈命中者（"你朋友的朋友欠钱不还"，你的风险传导上升）
- **网络中心度**：该客户在关联网络中的位置（中间人比边缘人风险更高）

智信分可加"共债人 / 担保人风险"特征；智融分通过引用智察、智信分间接获得。若要把图谱接入智察分做团伙识别，是有价值的方向。

## 六、小白常见问题（FAQ）

**Q1：为什么智察分满分 100，智信分满分 900？**
历史沿革不同。欺诈分习惯用 0-100 百分制（类似考试），信用分习惯用 300-900（类似央行征信的分段区间，更细腻）。两者不要直接比大小。

**Q2：页面上的分数是真实算出来的吗？**
演示系统里，有完整评分快照的客户用快照分数；旧数据客户（如张*明）用 `riskDims`（6 个风险维度分）**运行时推导**出三模型分数，保证页面永远有内容。推导公式：智察分 ≈ 风险维度加权均值；智信/智融分 ≈ 900 - 风险均值 × 系数。属于演示逻辑，不是真实模型重算。

**Q3："触发 / 关注 / 正常"是什么意思？**
- **触发**：这项数据已经踩线（如申贷 7 家 > 阈值 5 家），直接命中规则预警，一票否决式进处置流程
- **关注**：接近阈值（如同设备 3 个账号，阈值 5），待观察
- **正常**：正常参与评分，不影响分数

**Q4：模型分是最终决定吗？**
不是。模型分只是**辅助决策**。最终由审核员人工复核，拒绝 / 降额等动作必须留痕（页面"操作日志 / 人工干预留痕"可见）。这也是监管要求：机器给建议，人做决定，全程可追溯。

**Q5：规则命中预警 和 分值阈值预警 有什么区别？**
- **规则命中预警**（事件型）：某项数据独立踩线（多头 ≥5 家、命中灰名单），**不依赖总分**，直接触发
- **分值阈值预警**（状态型）：模型先算综合分，分数**碰撞区间**（智察 ≥70 高风险）触发，决定"多严重"
- 专业做法两者都有：规则说"哪错了"，分值说"多严重"，共同驱动处置流程

**Q6：页面上每个 Tab 都是干嘛的？**
| Tab | 一句话 |
|---|---|
| 得分 | 本次评分 + 为什么（维度拆解）+ 分数变化趋势 + 操作日志 |
| 预警与处置 | 分值预警 + 规则预警 + 处置流程进度 + 处置记录 |
