# 信息核验 — 核验规则配置页功能设计

> 本文档定义「信息核验」模块下「核验规则配置页」的产品功能设计。
> 该页面用于配置**多源并行核验单项报告**中 5 项数据源核验的规则参数，包括：开关、数据源接入、字段映射、判定条件、超时重试、操作权限等。
> 对应代码数据层：`SaaS/src/console/infoVerifyReport.ts`（`SingleResult` / `SubItem` / `Conclusion` 等类型）。

---

## 一、页面定位

| 维度 | 说明 |
|------|------|
| **所属模块** | 信息核验（贷前审核） |
| **页面名称** | 核验规则配置页 |
| **页面类型** | 配置型管理页（非列表，表单为主） |
| **访问入口** | 左侧菜单「信息核验」→「核验规则」 |
| **操作权限** | 系统管理员、风控主管可编辑；风控专员仅可查看 |
| **数据持久化** | 后端规则引擎配置库，支持版本管理与灰度发布 |

## 三、全局配置区

| 配置项 | 类型 | 必填 | 默认值 | 说明 |
|--------|------|:----:|--------|------|
| **规则集名称** | 文本 | 是 | — | 如「标准进件核验规则 V2.6」 |
| **版本号** | 文本 | 是 | 自动 | 格式 `V{major}.{minor}`，保存时自动递增 minor |
| **生效状态** | 单选 | 是 | 草稿 | `草稿 / 已生效 / 已下线`；仅一条「已生效」规则集可同时生效 |
| **适用范围** | 单选 | 是 | 全产品 | `全产品 / 指定产品`；指定产品时弹出多选产品列表 |
| **规则集描述** | 多行文本 | 否 | — | 用于说明本规则集的适用场景与变更原因 |

> 切换「已生效」时系统校验：5 项数据源开关中至少开启 1 项，且每项已开启的数据源至少配置 1 条判定条件。

## 四、5 项数据源规则卡片

### 4.1 Tab 导航

| Tab 标签 | 数据源标识 | 说明 | 对应代码 `icon` |
|----------|-----------|------|----------------|
| 公安实名 | `police` | 公安实名身份核验 | `police` |
| 银行卡四要素 | `unionpay` | 银行卡四要素核验 | `unionpay` |
| 运营商实名 | `operator` | 运营商手机号实名核验 | `operator` |
| 终端设备 | `device` | 终端设备风险库核验 | `device` |
| 联防联控 | `network` | 跨行业联防联控交叉核验 | `network` |

每个 Tab 内的规则卡片结构完全一致，以下以「公安实名」为例展开，其余 4 项在 4.7 节给出差异化字段。

### 4.2 数据源开关

| 配置项 | 类型 | 说明 |
|--------|------|------|
| **启用该数据源** | 开关（Toggle） | 关闭后，该数据源在「多源并行核验单项报告」中不发起调用，结论标记为 `未启用` |
| **是否为必核项** | 开关 | 开启后，该项结论为 `reject` 时直接触发系统级拒绝（无需等待其他数据源） |

### 4.3 数据源接入参数

| 配置项 | 类型 | 必填 | 默认值 | 说明 |
|--------|------|:----:|--------|------|
| **API 渠道** | 下拉单选 | 是 | — | 如「同盾多源并行核验 API V2.0」「百行征信 API」「中移互联 API」 |
| **调用地址** | URL | 是 | 根据渠道自动填充 | 支持覆盖修改 |
| **AppKey / 商户号** | 加密文本 | 是 | — | 敏感字段，前端脱敏展示（`****`） |
| **AppSecret** | 加密文本 | 是 | — | 同上 |
| **超时时间（ms）** | 数字输入 | 是 | 3000 | 接口调用超时阈值 |
| **熔断阈值** | 数字输入 | 否 | 5 | 连续失败 N 次后触发熔断，停止调用该渠道 |
| **熔断恢复时间（s）** | 数字输入 | 否 | 60 | 熔断后等待多久自动恢复探测 |

### 4.4 字段映射

将系统内部字段名映射到外部数据源返回字段名，支持「自动映射」（按字段名相同自动对齐）与「手动映射」。

| 系统内部字段 | 映射目标字段 | 数据类型 | 必填 |
|-------------|-------------|---------|:----:|
| 姓名 | `name` / `userName` / ... | string | 是 |
| 身份证号 | `idNo` / `idCard` / ... | string | 是 |
| 人脸比对相似度 | `faceScore` / `similarity` | number | 是 |
| 活体检测结果 | `livenessResult` / `liveCheck` | enum | 是 |

> 映射配置保存后，系统自动生成「映射校验」按钮，点击后向后端发送测试请求，验证映射字段是否能正确解析。

### 4.5 判定条件（核心）

针对该数据源的每一项 `SubItem`（子字段），配置其通过/预警/拒绝的判定条件。

#### 4.5.1 判定条件结构

每项子字段支持配置 1~N 条判定规则，规则之间按**优先级自上而下**匹配，命中即停止。

| 规则属性 | 类型 | 说明 |
|---------|------|------|
| **规则名称** | 文本 | 如「人脸比对通过」 |
| **字段** | 下拉 | 选择该数据源下的子字段（如「人脸比对相似度」） |
| **运算符** | 下拉 | `等于 / 不等于 / 大于 / 大于等于 / 小于 / 小于等于 / 包含 / 正则匹配 / 在集合中` |
| **阈值 / 目标值** | 文本/数字 | 根据运算符类型变化 |
| **结论** | 单选 | `通过(pass) / 预警(warning) / 拒绝(reject)` |
| **优先级** | 数字 | 1~99，数字越小优先级越高 |
| **是否启用** | 开关 | 临时禁用某条规则而不删除 |

#### 4.5.2 以「公安实名」为例的默认判定规则

| 子字段 | 规则名称 | 运算符 | 阈值 | 结论 | 优先级 |
|--------|---------|--------|------|------|:------:|
| 姓名 | 姓名一致 | 等于（申请人填报） | — | 通过 | 1 |
| 身份证号 | 身份证号一致 | 等于（申请人填报） | — | 通过 | 1 |
| 人脸比对相似度 | 高置信通过 | ≥ | 95 | 通过 | 1 |
| 人脸比对相似度 | 中置信预警 | ≥ | 80 | 预警 | 2 |
| 人脸比对相似度 | 低置信拒绝 | < | 80 | 拒绝 | 3 |
| 活体检测 | 活体通过 | 等于 | `通过` | 通过 | 1 |
| 活体检测 | 活体失败 | 等于 | `失败` | 拒绝 | 2 |

> 系统预置一套默认规则（如上），用户可在此基础上增删改。

### 4.6 结论映射规则

将子字段结论汇总为**数据源整体结论**（`SingleResult.conclusion`）的规则。

| 配置项 | 类型 | 说明 |
|--------|------|------|
| **汇总模式** | 单选 | `一票否决（任一子字段拒绝则整体拒绝）` / `加权计分（按子字段权重累加风险分）` / `自定义规则` |
| **默认结论** | 单选 | 所有子字段均通过时的整体结论，固定为 `通过` |
| **拒绝触发条件** | 条件组 | 当满足哪些子字段组合时，整体结论为 `拒绝` |
| **预警触发条件** | 条件组 | 当满足哪些子字段组合时，整体结论为 `预警` |

**默认「一票否决」模式示例**：
- 任一子字段结论 = `拒绝` → 整体结论 = `拒绝`
- 无拒绝但有子字段 = `预警` → 整体结论 = `预警`
- 全部子字段 = `通过` → 整体结论 = `通过`

### 4.7 5 项数据源的差异化字段

#### ① 公安实名身份核验（`police`）

| 子字段 | 数据类型 | 说明 |
|--------|---------|------|
| 姓名 | string | 公安库返回的姓名 |
| 身份证号 | string | 公安库返回的身份证号 |
| 人脸比对 | string / number | 相似度百分比或文本结论 |
| 活体检测 | enum | `通过 / 失败 / 不确定` |

**必核项默认**：开启（身份真实性是贷前审核的基础）。

#### ② 银行卡四要素核验（`unionpay`）

| 子字段 | 数据类型 | 说明 |
|--------|---------|------|
| 卡号 | string | 银行卡号一致性 |
| 姓名 | string | 持卡人姓名一致性 |
| 身份证号 | string | 持卡人身份证号一致性 |
| 预留手机号 | string | 银行预留手机号一致性 |

**差异化配置**：
- 支持配置「卡 Bin 校验」开关：开启后先校验卡号是否属于支持的银行列表
- 支持配置「二要素/三要素/四要素」模式：根据产品合规要求选择核验要素数量

#### ③ 运营商手机号实名核验（`operator`）

| 子字段 | 数据类型 | 说明 |
|--------|---------|------|
| 手机号 | string | 手机号一致性 |
| 实名姓名 | string | 运营商实名姓名一致性 |
| 入网时长 | number（天） | 入网天数 |
| 在网状态 | enum | `正常 / 停机 / 销号 / 未实名` |

**差异化配置**：
- 入网时长阈值：可配置「入网 < N 天」触发预警（默认 30 天）
- 在网状态映射：自定义各状态对应的结论（如「停机」→ 预警，「销号」→ 拒绝）

#### ④ 终端设备风险库核验（`device`）

| 子字段 | 数据类型 | 说明 |
|--------|---------|------|
| 设备指纹 | string | 设备唯一标识 |
| 关联身份数 | number | 该设备近期关联的身份数量 |
| Root/越狱状态 | enum | `是 / 否` |
| 模拟器检测 | enum | `是 / 否` |

**差异化配置**：
- 关联身份数阈值：可配置「7 日内关联 ≥ N 个身份」触发拒绝（默认 3 个）
- 关联时间窗口：可调整统计周期（7 日 / 30 日 / 90 日）
- 设备指纹相似度：可配置模糊匹配阈值（防止设备参数微调绕过）

#### ⑤ 跨行业联防联控交叉核验（`network`）

| 子字段 | 数据类型 | 说明 |
|--------|---------|------|
| 手机号黑名单 | string / number | 命中条数或结论文本 |
| 身份证黑名单 | string / number | 命中条数或结论文本 |
| 关联逾期 | number | 历史逾期记录条数 |
| 共债网络 | enum | `未发现 / 轻度 / 中度 / 重度` |

**差异化配置**：
- 支持配置「黑名单库源」：选择对接的黑名单数据源（同盾 / 百融 / 自建库）
- 命中条数阈值：可配置「命中 ≥ N 条」触发拒绝（默认 1 条）
- 共债网络映射：自定义各等级对应的结论

### 4.8 超时与重试策略

| 配置项 | 类型 | 默认值 | 说明 |
|--------|------|--------|------|
| **单次超时（ms）** | 数字 | 3000 | 单接口调用超时时间 |
| **重试次数** | 数字 | 1 | 失败后的自动重试次数 |
| **重试间隔（ms）** | 数字 | 500 | 每次重试之间的等待时间 |
| **降级策略** | 单选 | `返回超时标记` | `返回超时标记（人工介入）/ 忽略该项（按通过处理）/ 阻断流程（按拒绝处理）` |

### 4.9 规则提示类型映射（`rulePromptType`）

将数据源整体结论映射为规则提示类型，用于在报告中渲染不同颜色的提示标签。

| 整体结论 | 规则提示类型 | 颜色 |
|---------|-------------|------|
| 通过 | `pass` | 绿色 |
| 预警 | `warning` | 黄色/琥珀色 |
| 拒绝 | `reject` | 红色 |

支持自定义映射：如将某些特定场景的「预警」映射为 `pass`（业务豁免场景）。

## 五、规则变更日志

| 字段 | 说明 |
|------|------|
| **版本号** | 规则集版本 |
| **操作类型** | `创建 / 编辑 / 生效 / 下线 / 回滚` |
| **操作人** | 系统用户 |
| **操作时间** | 精确到秒 |
| **变更摘要** | 自动生成的变更说明（如「修改了运营商入网时长阈值：30→60 天」） |
| **操作** | `查看详情 / 回滚到此版本` |

> 回滚操作：将当前规则集恢复到指定历史版本的状态，恢复后版本号自动递增。

## 六、权限与审批

| 角色 | 查看 | 编辑 | 生效/下线 | 回滚 |
|------|:----:|:----:|:---------:|:----:|
| 系统管理员 | ✓ | ✓ | ✓ | ✓ |
| 风控主管 | ✓ | ✓ | ✓ | ✗ |
| 风控专员 | ✓ | ✗ | ✗ | ✗ |
| 数据分析师 | ✓ | ✗ | ✗ | ✗ |

- **编辑后保存**：先保存为「草稿」状态，需经「生效」操作后才对生产环境生效。
- **生效审批**：风控主管点击「生效」时，系统弹出确认框要求填写「生效原因」，并记录审批日志。
- **灰度发布（未来扩展）**：支持按产品 / 按客群灰度生效新规则集。

## 七、与报告详情页的衔接

核验规则配置页修改的参数，直接影响「信息核验报告详情页」中以下区域的展示：

| 报告详情区域 | 受影响的配置项 |
|-------------|--------------|
| **三、多源并行核验单项报告** | 5 项数据源的开关、子字段、结论、耗时 |
| **五、数据交叉融合综合报告** | 数据源整体结论作为交叉比对的输入 |
| **领衔区 2 · 核验过程** | 各核验步骤的 conclusion 颜色（通过绿/预警黄/拒绝红） |
| **六、单项核验全量操作日志** | 数据源调用失败 / 超时产生的日志 |

> 规则配置生效后，新进入件的申请按新规则执行；历史已生成的报告不受影响（报告为快照）。
