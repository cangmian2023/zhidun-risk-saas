# 需求处理总结文档（2026-08-05）

> 本文件记录在 2026-08-05 当天，针对用户提出的需求（第 11 项审计、5–10 重做、统一模板、第 12 项业务流程配置），我所采取的处理方式、关键决策与落地结果。

## 一、总体处理策略

用户的核心洞察：**5–10 建立在错误的 4.x 之上，必须先厘清 4.x 的真相，重做才有意义。**

据此我把工作拆为三阶段顺序推进：
```
审计（第11项）  →  重构（5–10 统一模板）  →  新增（第12项 业务流程配置）
```

---

## 二、第 11 项：列表数据审计

**方法**：逐一比对页面渲染数据与本地 JSON 磁盘内容
（`midDataSources.json` / `midMetrics.json` / `midStrategy.json` / `midDashboards.json`）。

**结论**：
- ✅ **列表数据本身是正确的** —— 6 个数据源 / 16 个指标 / 策略对象 / 6 个看板，与磁盘完全一致。
- ❌ 用户记在 11 里的"错误"实际不在数据，而在**来源标签**：
  1. **冗余标签**：`配置JSON·配置JSON`、`实时计算·实时计算`（`SourceTag` 未去重）；
  2. **色系错误**：策略 / 页面配置被标橘（样例），按 `AGENTS.md` 应为蓝（配置）；
  3. **误标**：字段清单 / 可视化组件被标灰（实时计算），实为配置。

**处理**：将结论定性为"数据无误、问题在标签"，在 5–10 重做中统一修正，而非返工数据。

## 三、第 5–10 项：统一模板重构

### 3.1 共享模板 `ConfigTemplate.tsx`（新建）
集中管理以下共享资产，实现"改一处、全局生效"：
- 面包屑 `CONFIG_CRUMB = '零售信贷风控 / 管理中心'`、`crumb()` 构造器；
- 容器 `CONFIG_CONTAINER`、标题/文案映射（`SRC_TYPE_LABEL` / `METRIC_TYPE_LABEL` / `FREQ_LABEL` / `OUTPUT_LABEL` / `OP_LABEL` / `WTYPE_LABEL`）；
- `fmt()` 统一格式化；
- `ConfigListPage`（支持 `tabs` / `panelActions` / `modalWidth` / `onView` 带 `tabKey`）；
- `ConfigDetailPage`（支持 `crumbParts` / `infoCells` / `children`=Panels）。

### 3.2 8 个页面接入同一骨架
| 类型 | 页面 | 接入组件 |
|------|------|----------|
| 列表页 | MidDataSourceConfig / MidMetricConfig / MidStrategyConfig / MidDashboardConfig | `ConfigListPage` |
| 详情页 | MidDataSourceDetail / MidMetricDetail / MidStrategyDetail / MidDashboardDetail | `ConfigDetailPage` |

### 3.3 标签体系修复
- **`SourceTag.tsx` 去重**：当 `label` 与 `KIND_META[kind].label` 相同时，不再拼 `·xxx`，消除 `配置JSON·配置JSON`。
- **`ui.tsx` 列标签迁表头**：`DataTable` 的 `Column.tag` 由"每个单元格渲染"改为"仅在表头渲染一次"，消除单页 450 个重复标签刷屏（4.0 / 4.5 投诉根因）。
- **色系校正**：`midStrategy` / `midDashboards` 由橘（样例）转蓝（配置），与 `AGENTS.md` 最高优先级一致。

### 3.4 收益
此后如需调整面包屑、容器、文案、标签形态，**只需改动 `ConfigTemplate.tsx` 一处**，满足用户"同一个模板，修改方便"的硬性要求。

## 四、第 12 项：业务流程配置（新增）

### 4.1 方案决策（已与用户确认）
- **复用模板内 `businessFlow`**（而非新建独立 `midFlows.json` 库）。
- 理由：4 个运行时审核页（信息核验 / 信用风控 / 欺诈识别 / 进件审核）本就按 `gradeId + flowGraphs` 读取各模板的 `businessFlow`，**复用即零改动生效，风险最低**。

### 4.2 实现
- 新页 `MidBizFlowConfig.tsx`，菜单 key `cm:biz-flow`，置于管理中心最末「业务流程」组，图标 `work_flow`。
- 按 4 个业务域分签，各自编辑对应报告模板内的 `businessFlow`。
- 完整复用 `FlowCanvasEditor`（添加流程 → 画布 → 节点配置 → 保存本地），写回经 `updateTemplate` 自动落盘 `templateSeed.json`。

### 4.3 验证点
编辑并保存一条流程后，对应审核页的"操作列按钮"与"详情页第二张卡片"应同步反映配置变化。
