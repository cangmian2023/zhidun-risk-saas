# 数据源管理 · 详情页设计文档

> 对应 `record/0805.md` 第 4 项（4.0~4.5）整改要求。先出设计，再实现功能与样例数据。

## 0. 背景与问题（来自 4.0~4.5）

- **4.0 标签内容错误**：原标签显示 `配置JSON·配置JSON`（大类名重复），且没有指向具体字段，看不出"这一项来自哪个 JSON 的哪个字段"。
- **4.1 列表读取**：列表本来就读本地 json 全量；"4 行"=4 个数据源条目，"23 行"=所有数据源样例行总和，是概念差异，需在 UI 上区分清楚。
- **4.2 列表字段标签**：列表各列（名称/类型/状态/字段数/样例行/更新时间）都标了"配置JSON"，但没体现它们来自 `midDataSources.json` 的哪个字段。
- **4.3 详情页缺连接信息**：数据源应有连接配置（host / username / password 等），原详情页完全没有，需重做并先出本设计。
- **4.4 重审 4.2**：随 4.2 一并修正。
- **4.5 详情页标签错误**：① 顶部"编辑"旁的 `配置JSON·配置JSON:midDataSources.json` 重复且无意义；② "字段清单"被标成"实时计算·字段口径"（灰），但字段清单是配置 JSON，应标蓝；③ 字段行又标"配置JSON·配置JSON"。

## 1. 数据模型（midDataSources.json）

单个数据源对象：

| 字段 | 类型 | 说明 | 来源标签 |
|------|------|------|----------|
| id | string | 主键 | 配置JSON·midDataSources.json.id |
| name | string | 数据源名称 | 配置JSON·midDataSources.json.name |
| type | 'sample'\|'api'\|'sql' | 类型 | 配置JSON·midDataSources.json.type |
| desc | string | 描述 | 配置JSON·midDataSources.json.desc |
| conn | MidConnConfig | 连接配置（sample 无） | 配置JSON·midDataSources.json.conn.* |
| fields | MidField[] | 字段清单 | 配置JSON·midDataSources.json.fields |
| rows | Record[] | 样例数据行 | 样例JSON·`<dsId>`.* |
| status | string | 连接状态 | 配置JSON·midDataSources.json.status |
| updatedAt | string | 更新时间 | 配置JSON·midDataSources.json.updatedAt |

### 连接配置 MidConnConfig（扩展后）

原类型缺 host/ip、port、database、username，本次补齐：

- **api 类型**：`method`(GET/POST)、`authType`(none/bearer/apikey/basic)、`host`(域名/IP)、`account`(账号)、`password`(密钥)
- **sql 类型**：`dbType`(mysql/oracle/postgres)、`host`(IP)、`port`、`database`(库名)、`username`、`password`、`connStr`(连接串)、`query`(查询SQL)
- **sample 类型**：无 conn，详情页显示"本地样例数据源，无需连接配置"

## 2. 详情页结构（自上而下）

1. **页头**：名称 + 描述 + 操作（编辑 / 返回）+ 来源标签 `配置JSON·midDataSources.json`
2. **基本信息卡**（InfoCell 网格）：类型 / 状态 / 字段数 / 样例行 / 更新时间
   - 每项标 `配置JSON·midDataSources.json.<字段>`
3. **连接信息 Panel**
   - sample：`本地样例数据源，无需连接配置`
   - api：请求方法、鉴权方式、域名(host)、账号、密码 —— 每项 `配置JSON·midDataSources.json.conn.<字段>`
   - sql：数据库类型、主机(host)、端口、库名、用户名、密码、连接串、查询SQL —— 同上
   - 密码字段做掩码显示（如 `••••••`）+ "显示"切换
4. **字段清单 Panel**（表：字段key / 标签 / 维度·度量 / 类型 / 单位）
   - 来源：`配置JSON·midDataSources.json.fields.<key>`（**蓝，不再标灰**）
5. **数据预览 Panel**（样例数据表）
   - 来源：`样例JSON·<dsId>.<字段>`；列头可附具体样例值说明
6. **被指标库引用 Panel**：引用此数据源的指标按钮列表
   - 来源：`配置JSON·midMetrics.json`（读取）

## 3. 数据来源标签规范（统一修复 4.0/4.5）

- 格式：`{大类}·{来源路径}`，大类固定为 配置JSON / 样例JSON / 实时计算（三色不变）。
- **禁止"配置JSON·配置JSON"重复**：调用 `Cfg/Sam/Cal` 时**只传 `value=来源路径`，不再传 `label="配置JSON"`**（组件默认大类名已含）。
- 来源路径写"文件 + 字段"具体位置，例如：
  - `midDataSources.json.name`、`midDataSources.json.conn.host`
  - `ds_customer.cust_name`（样例数据）
  - 实时计算传公式文本
- 样例数据如需证明"值来自 json"，在 Panel 说明区写 `字段=当前样例值`，不塞进小标签以免过长。

## 4. 列表页（修复 4.1/4.2）

- 列表读取本地 json 全量（`useMidDataSources` → `/api/load-mid`）。
- 每行 = 1 个数据源；**列表行数 = 数据源数**，与"样例行数"是两回事，UI 上分开展示避免混淆。
- 列表列标签改为具体路径：
  - 名称 → `配置JSON·midDataSources.json.name`
  - 类型 / 状态 / 字段数 / 样例行 / 更新时间 → 对应 `midDataSources.json.<字段>`
- 顶部"样例数据：N 行"明确标注为"所有数据源样例行总和"。
