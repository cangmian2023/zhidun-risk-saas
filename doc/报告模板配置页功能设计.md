# 报告模板配置页 · 功能设计

> 本文档定义「零售信贷风控 — 贷前审核」模块下「报告模板配置页」的产品功能设计。
> 该页面用于配置四大报告（信息核验 / 信用风控 / 欺诈识别 / 决策报告）的展示模板，包括：报告内容（分段/字段显隐）、评分展示方案、不同评分对应的结论、样式主题、导出模板。
> 对应代码展示端：`SaaS/src/console/PreVerifyDetail.tsx`、`CreditReportDetail.tsx`、`FraudScheme4Detail.tsx`（决策报告详情页待建）。
> 设计模式参考已落地的「核验规则配置页」（`VerifyRuleEditor.tsx`）：左侧模板列表 + 右侧配置面板。

## 一、页面定位与边界

### 1.1 基础定位

| 维度 | 说明 |
|------|------|
| **所属模块** | 零售信贷风控 — 贷前审核 |
| **页面名称** | 报告模板配置 |
| **页面类型** | 配置型管理页（左侧模板列表 + 右侧配置面板） |
| **访问入口** | 左侧菜单「公共配置」→「报告模板」（或各报告子模块下独立的「报告模板」入口） |
| **操作权限** | 系统管理员、风控主管可编辑；风控专员仅可查看与切换模板 |
| **数据持久化** | 后端模板配置库，支持多模板并存、版本管理与默认模板设置 |

### 1.2 与信用模型配置的关系

| 维度 | 信用模型配置 | 报告模板配置 |
|------|-------------|-------------|
| **关注点** | 评分公式与参数（如何算分） | 报告展示与结论（分数如何展示、如何决策） |
| **使用者** | 风控策略岗、系统管理员 | 风控主管、系统管理员 |
| **修改影响** | 影响新进入件的评分计算 | 影响新进入件的报告渲染与业务操作流程 |
| **关系** | 信用模型输出「分数」 | 报告模板接收「分数」→ 展示 + 决策分流 |

> **核心原则**：信用模型配置是「评分引擎」，报告模板配置是「评分结果的展示与业务应用」。二者独立配置、组合生效。

## 二、在贷前审核与贷中监控中的作用

### 2.1 贷前审核中的作用

1. **报告内容按需展示**：不同产品/客群的报告展示内容不同。如信用贷需要展示完整的信用风控六维分析，小额快贷只需要展示简化版评分与决策建议。
2. **评分展示标准化**：统一各报告的评分展示方式（大数字/环形图/进度条）、等级划分、颜色语义，确保信审员快速理解风险等级。
3. **结论灵活配置**：不同产品可以配置不同的评分区间 → 决策建议 → 可执行操作的映射。如A产品「60分以上自动通过」，B产品「70分以上才自动通过」。
4. **监管合规适配**：不同监管要求下，报告导出格式、水印、签名区、留痕字段可灵活配置。

### 2.2 贷中监控中的作用

1. **模板迭代优化**：根据贷后表现（逾期率、坏账率、信审员反馈），调整报告中展示的重点字段与风险提示方式。
2. **A/B 测试**：不同客群使用不同报告模板，对比信审效率、误杀率、通过率，找出最优展示方案。
3. **多租户适配**：SaaS 平台服务多个机构客户时，每个客户可配置独立的报告模板（品牌色、Logo、字段显隐、决策阈值）。

## 六、Tab 一：报告内容配置

### 6.1 功能概述

配置报告中「显示哪些分段、每个分段内显示哪些字段、分段的展示顺序」。**核心模型：每个分段有且仅有单一来源（sourceType）**，字段即该来源的具体产出项。来源类型决定分段如何取数，也决定其下每个字段能配置什么：

| 来源类型 | 含义 | 典型例子 | 该段可配置什么 |
|---------|------|-----------|------------|
| `data_source` 数据源 | 来自进件表单 / 用户上传的**结构化原始数据**，存于某张库表 | 基本信息 | **① 配库表连接**（数据库类型/IP/端口/账号/密码/库/表）→ ②「读取表字段」→ ③ 勾选要在报告展示的字段（取自该表，不可凭空新增；敏感字段默认脱敏） |
| `api` 接口调用 | 调某引擎/模型得到，必有「输入→输出」；**返回图片 / 视频等非结构化内容也走接口**（数据源只认表字段，配不出图片/视频容器） | 异常值模型卡、决策建议、征信查询、证件影像（图片 / 视频） | **① 请求栏（Postman 风格）：方法下拉(GET/POST/PUT/PATCH/DELETE) + URL** → ② Tabs：**参数 Params**（输入参数：key←数据来自、是否必填）/ **请求头 Headers** / **请求体 Body**（类型 none/JSON/form-data/x-www-form ＋原文）/ **代码 Code**（粘贴 cURL/HTTP 统一代码一键解析填充，或反向生成代码）→ ③「输出字段」表（返回值：显示名/类型/容器/是否展示，可新增） |
| `rule_set` 规则集 | 系统内已配置的规则合集碰撞，得到命中/未命中 | 多源并行核验、各欺诈详情、黑名单 | **① 选规则合集**（合集来自系统内配置）→ ② 勾选该合集下「用/不用」的规则项 → ③ 每项配「命中显示 / 未命中显示」 |

> 设计要点：**字段不是内置写死的**，而是在本 Tab 前端「配出来」的——但字段**源自来源本身**：数据源字段来自"读取的表结构"、规则项来自"所选规则合集"，二者都**不能凭空新增**，只能显隐/配置；只有接口类的「输出字段」可按返回值新增。内置 `SECTION_CATALOG` 仅作为新建模板时的**初始种子内容**，全部可改可删。

### 6.2 交互方式

- **分段列表**：以卡片/行列出该报告类型下的所有分段，每段带来源类型**醒目分类标识**——卡片**左边框 4px 按来源着色（数据源=绿 / 接口=蓝 / 规则集=紫）** + 头部底色随来源类型 + 右侧来源彩色标签（白底描边加粗），一眼区分三类来源。
- **新增分段**：面板顶部按来源类型三个按钮「＋ 数据源 / ＋ 接口调用 / ＋ 规则集」，新建空白分段（数据源/规则集段初始无字段，待配置来源后生成；接口段初始有 1 个空输出字段待填）。
- **删除分段**：每段「删除分段」按钮（确认后连其下字段一并删除）。
- **上移/下移**：每段有 ↑/↓ 调整顺序（段内字段顺序由来源结构决定，不单独排序）。
- **来源类型不在卡片上切换**：来源类型在「新增分段」时已由对应按钮（数据源/接口/规则集）确定，每段右侧只保留**彩色标签**展示来源，不再提供切换下拉（避免误切成空配置）。如需换类型，删除后按对应按钮重建。
- **分段按 `homeTab` 归属不同 Tab（算得类不占「报告内容」）**：**四种报告类型统一**——每个类型的**首段（评分总览 / 模型卡）**归属「评分方案」Tab、**第二段（结论 / 处置建议）**归属「审核操作」Tab，与信息核验口径一致，故这些卡片**不出现在「报告内容配置」里**。具体映射（`SCORE_SECTION` / `FLOW_SECTION` 常量，按段 id 语义匹配而非固定前两行——决策报告的结论卡是 `decision_suggestion`「最终决策建议」，而非目录第 2 条 `verify_summary`「信息核验摘要」）：信息核验 `score_model`→评分方案、`conclusion_process`→审核操作；信用风控 `credit_score_overview`→评分方案、`credit_conclusion`→审核操作；欺诈识别 `fraud_score_model`→评分方案、`disposal_bar`→审核操作；决策报告 `decision_overview`→评分方案、`decision_suggestion`→审核操作。`*_logs` 操作日志段不在任何 Tab 编辑，由详情页「基础信息」面板的「在报告中显示操作日志」开关（`showOpLog`）统一控制（不再单列独立面板，避免过于突出）。「报告内容配置」Tab 只渲染 `homeTab==='content'` 的分段（数据源/接口/规则集类）；抽离 `renderSectionCard(s, {showConfigBtn,showDelete,showMove})` 供三 Tab 复用（score/flow 段无配置来源/删除/移动按钮，仅展示勾选项）。
- **显示/隐藏**：分段有 Checkbox 控制整段显隐（至少保留 1 个，仅剩 1 个时置灰）；字段的展示与否在**卡片下方展示层**直接勾选——数据源=表字段勾选、接口=输出字段勾选、规则集=列表"用/不用"勾选。
- **卡片展示层为带表头的列表（每个字段都是一行，且都有表头）**：
  - 数据源：`[启用] 字段名（原始，只读） | 提示标签（显示名，可编辑） | 类型(从表结构读取) | 显示方式 | 脱敏规则 | 说明` —— 首列复选框即「启用/禁用」；「字段名」是库表原始列名（只读，如 name / three），「提示标签」是前端展示名（可编辑，如 姓名→张三）；类型列只读（varchar/int/datetime…），显示方式按列类型推荐（标「（推荐）」）可改，脱敏规则/说明卡片上即可改。
  - 接口：`[启用] 显示名(标签) | 字段 key | 类型 | 显示方式 | 单位 | 对齐 | 操作(删除）` —— 输出字段支持**增/删/改/查**：可编辑 显示名 与 字段 key、切换类型（string/number/enum/boolean/date/image/file/json）、改显示方式/单位/对齐，并可在卡片右下「＋ 输出字段」新增；类型按类型推荐显示方式可改，单位/对齐卡片上即可配。
  - 规则集：`[启用] 规则名 | 说明 | 状态(已启用/未启用)`。
- **每个字段的「显示方式」与「标签(提示标签/显示名)」需在前端配置**：不同数据类型在前端呈现形式不同（图片要用图片容器、文件要用文件下载容器…），故字段需配置：① **标签（提示标签，报告中的显示名）**；② **显示方式（原"对象容器"）** `RenderContainer = 文本/图片/文件/标签组/链接/表格`，按返回值类型有推荐默认（标「（推荐）」）但可显式覆盖（如把 number 改成「标签组」）。**配置位置统一在卡片列表上直接改**（不再进弹窗配字段）。
- **配置项与展示项分离（关键改动）**：原本「配置项」（库表连接 / API 地址+输入输出 / 规则集选择+规则项用不用）直接摊在分段卡片里，与展示项混在一起显得凌乱。现改为：
  - **卡片只留展示层**：只负责"报告中展示哪些项"的勾选/汇总（带表头列表），干净清爽。
  - **「配置来源」弹窗**：每段右上「配置来源」按钮打开一个 Modal（接口类用更宽的 `max-w-2xl`），里面集中填写该类来源的全部**配置项**，并带一个**「测试」按钮**做可用性校验。
- **三来源各自「配置来源」弹窗内容**：
  - `data_source` 段：**① 数据库连接表单**（数据库类型/IP/端口/用户名/密码/库名/表名）+「读取表字段」按钮（读取后带回**列类型**，并自动按列类型给出推荐显示方式、按字段名识别脱敏规则）/ 底部「**测试连接**」按钮。字段的「启用 / 提示标签（显示名）/ 显示方式 / 脱敏规则 / 说明」**全部在卡片上直接配置**，弹窗内不再配字段。
  - `api` 段：**① 接口表单**（接口名/API 地址/请求方式 + Tabs 参数/请求头/请求体/代码）；**② 输入参数表**（参数 key ← 数据来自、是否必填、可增删）；底部「**测试接口**」按钮。输出字段的「**增 / 删 / 改 / 查**」（显示名 / 字段 key / 类型 / 显示方式 / 单位 / 对齐）**全部在卡片上直接操作**，弹窗内不再配输出字段。
  - `rule_set` 段：**① 规则合集选择（复杂下拉搜索框）**——点击展开搜索框，可搜「合集名 / 规则名 / 规则说明」，命中关键词高亮；每项显示「N 条规则」徽标 + 前几条规则名 chip；支持 ↑/↓ 键移动、Enter 选中、Esc 关闭、点击外部收起；首项「（请选择 / 清空）」可清空合集。选中后触发下方规则项网格；**② 规则项网格**（每项"用/不用"勾选 + 命中显示 + 未命中显示 + 命中即拒（该条命中即整笔申请拒绝））；底部「**测试规则集**」按钮。已启用规则以列表汇总在卡片。
  - **每个分段「上分」配置（参与报告总分）**：每张卡片底部均带「上分」区——「参与报告总分」复选框 + 加分/扣分选择 + 加(扣)多少 + 最高分 + 最低分 + 权重，五项均可逐卡配置（正常记加、异常记扣，并限定上下限与权重占比）。配置后该卡可作为报告总分的构成项（与「评分方案」里的总分加权构成配合）。
  - **规则集类「命中即拒」是逐条规则属性（非整卡开关）**：在规则项网格中，每条规则都有独立的「命中即拒」复选框——勾选后该**单条规则**一旦命中即整笔申请拒绝（与是否参与总分无关，也不依赖「上分」开关）；不勾选则该规则仅按权重累计风险、不会触发整笔拒。因此「命中即拒」从规则项层面配置，而非卡片级。
  - **「评分方案」与「审核操作」Tab 首行配置（报告卡片显隐 + 标题）**：评分方案 Tab 顶部第一行控制该类型「评分总览 / 模型卡」（信息核验=得分计算、信用风控=信用评分总览、欺诈识别=欺诈风险评分模型卡、决策=综合决策总览）的「是否显示」+「卡片标题」；审核操作 Tab 顶部第一行控制该类型「结论 / 处置建议卡」（信息核验=结论与终审、信用风控=结论与终审操作卡、欺诈识别=处置建议与操作栏、决策=最终决策建议）的「是否显示」+「卡片标题」。标题留空则用默认。
- **测试按钮（`testSourceConfig`）**：弹窗底部按来源类型给出"测试连接 / 测试接口 / 测试规则集"，点击后模拟校验当前来源配置并返回结构化结果（成功绿框 / 失败红框 + 明细 + 耗时 ms）：
  - 数据源：校验 IP/端口(1–65535)/必填项格式；通过再校验是否已「读取表字段」；成功回显 `库类型·IP:端口 / 库·表 / 读取到 N 个字段`。
  - 接口：校验地址须 `http(s)://` 开头、至少 1 个输出、输出 key/显示名非空、必填输入需映射来源；成功回显 `请求方式+地址 / 输入参数数 / 返回输出字段数`。
  - 规则集：校验已选合集、至少启用 1 条规则；成功回显 `规则合集名 / 启用 M / 共 N 条规则 / 命中显示文案`。

## 七、Tab 二：评分展示配置（得分方案）

### 7.1 功能概述

配置报告中评分结果的展示方式、评分等级划分、等级名称与颜色。不同报告类型的评分口径不同，配置项有所差异。

### 7.2 评分展示方式

| 配置项 | 类型 | 选项 | 默认值 | 说明 |
|--------|------|------|--------|------|
| **评分展示组件** | 单选 | `大数字 / 环形图 / 进度条 / 仪表盘` | 大数字 | 评分在报告顶部的展示形式 |
| **显示评分说明** | 开关 | — | 开启 | 是否显示「越高越好/越高越危险」等说明文案 |
| **显示阈值刻度条** | 开关 | — | 开启 | 是否显示评分区间颜色条 |
| **显示构成项分解** | 开关 | — | 开启 | 是否显示评分的维度/指标分解 |
| **显示风险标签** | 开关 | — | 开启 | 是否显示风险标签（如设备群控/团伙欺诈） |

### 7.2.5 总分计算方式（加权构成）

> **算总分**：报告顶部的总分由各构成项按权重**加权求和**得到。本区块配置各项名称与权重（合计应为 100%），与下方「7.3 评分等级划分（分值分段）」配合——先算总分，再按区间落入对应风险档。

| 配置项 | 类型 | 说明 |
|--------|------|------|
| **构成项名称** | 文本 | 如 设备群控 / 黑名单命中 / 身份 / 信用历史；可增删 |
| **权重（%）** | 数字 | 各项权重之和应为 100%，非 100% 时给出黄色提示 |
| **权重合计** | 自动 | 实时累加显示，不等于 100% 时提示调整 |
| **＋ 新增构成项** | 按钮 | 增加一行空白构成项 |

各报告类型预置默认权重（可在前端改）：信息核验（设备群控35/黑名单命中30/资料异常20/行为异常15）、信用风控（身份20/还款25/信用历史25/行为10/设备10/关联10）、欺诈识别（设备关联30/团伙欺诈25/黑名单25/资料造假20）、决策报告（信息核验异常值34/信用评分33/欺诈评分33）。

### 7.3 评分等级划分（按报告类型区分）

|------|:--------:|:--------:|:----:|:--------:|
| 安全 | 0–20 | 低 | 🟢 绿 | 风险可控 |
| 关注 | 21–50 | 中 | 🟡 黄 | 中等风险 |
| 警示 | 51–80 | 高 | 🟠 橙 | 较高风险 |
| 高危 | 81–100 | 极高 | 🔴 红 | 极高风险 |

## 八、Tab 三：审核操作配置

### 8.1 功能概述

配置不同评分等级对应的：自动审核决策、人工审核初始状态、可执行操作、决策建议文案、授信额度比例。这是报告模板配置的核心业务配置，直接决定进件的风控流程。

> **与「评分方案」的联动（重构要点）**：结论行与评分方案中的等级按 **index 显式对齐**（由 `syncFlowToGrades()` 保证），不再依赖等级名称字符串匹配。
> - **第 0 行固定为「计算中」**：评分尚未得出的初始态，自动审核=处理中、人工状态=核验计算中、仅可查看，该行**不可配置**（gradeId 固定为 `—`）。
> - 其后每一行一一对应「评分方案」里的第 i 个等级；在评分方案里**改名 / 新增 / 删除等级**，结论会**自动同步跟随**（已配置项尽量保留）。
> - 因此结论里**无需再单独命名等级**，等级名称/数量完全由评分方案驱动。

### 8.2 结论配置表

以表格形式展示「评分等级 → 结论」的映射关系，首行为固定「计算中」态，其后每行对应评分方案中的一个等级。

| 配置项 | 类型 | 说明 |
|--------|------|------|
| **评分等级** | 只读 | 取自「评分方案」中的等级，第 0 行固定显示「计算中」（不可配置，不对应任何等级） |
| **自动审核决策** | 单选 | `通过 / 预警 / 拒绝 / 处理中` |
| **人工审核初始状态** | 单选 | `— / 待确认 / 待审核 / 核验计算中` |
| **决策建议文案** | 文本 | 该等级在报告中显示的决策建议，如「信用良好，建议正常授信」 |
| **授信额度比例** | 数字 | 该等级可获得的授信额度占申请额度的百分比（0%–100%） |
| **可执行操作** | 多选 | 该等级下审核员可执行的操作（见 8.3） |
| **是否需要人工复核** | 开关 | 开启后，该等级的进件必须经人工审核才能办结 |
| **复核级别** | 单选 | `单人复核 / 双人复核 / 初审+终审两级` |

## 十一、实时预览（独立子页面）机制

### 11.1 预览入口与独立子页面

- 实时预览**不再内嵌在详情页**，改为点击详情页顶栏 [预览] 按钮（列表卡片的「预览」操作亦同）跳转到独立子页面 `cm:report-template-preview?id={模板ID}`。
- 子页面为**独立路由、全屏渲染**，与详情页是「详情 → 预览」的二级跳转关系；顶部 `DetailHeader` 提供「← 返回详情配置」一键回到原模板（携带 `?id=` 参数定位到对应模板详情）。
- 子页面**只读展示**，不保存任何配置；编辑配置需回到详情页。

### 11.2 预览数据

- 预览使用**真实样例数据**（定义在 `reportTemplateData.ts` 的 `PREVIEW_SAMPLE`：按报告类型内置各分段/字段的真实样例值），渲染出报告**真实长相**（评分卡 + 阈值刻度条 + 各分段字段），而非占位框。
- 状态切换选项来自同文件的 `PREVIEW_STATES`，按报告类型提供：
  - 信息核验：`安全 / 关注 / 警示 / 高危`（对应异常值 12 / 40 / 65 / 90，**越高越危险**）
  - 信用风控：`A级 / B级 / C级 / D级`
  - 欺诈识别：`极低 / 低 / 中 / 高 / 极高`
  - 决策报告：`优先通过 / 通过 / 限制额度 / 严格限制 / 拒绝`
- 子页面顶部另提供「**以角色预览**」下拉（系统管理员 / 风控主管 / 风控策略岗 / 风控专员 / 数据分析师）：仅改变本页**可编辑态的呈现**（如风控专员下编辑控件置灰），用于让配置者感知权限差异，**不影响模板真实配置权限**。

### 11.3 预览渲染策略

- 子页面读取 `PREVIEW_SAMPLE` 真实样例数据，进入即渲染，与真实报告详情页 **1:1 还原**，使用同一套 `Panel` 组件。
- 子页面不支持交互（按钮点击、弹窗展开等仅作展示，不触发实际逻辑）。
- （历史方案中的"300ms debounce 实时联动"已废弃，改为子页面进入时一次性渲染。）
- 预览卡片顺序：评分卡（header）→ **「结论与终审」卡片**（受模板「审核操作」Tab 的 `flowBlock.show` + `flowBlock.title` 控制，标题留空回退「结论与终审」）→ **「得分计算」卡片**（受模板「评分方案」Tab 的 `scoreBlock.show` + `scoreBlock.title` 控制，标题留空回退「得分计算」，卡片内列出「参与上分」的分段明细：分段名 / 加分·扣分 / 分值 / 区间 / 权重，取自各分段上分配置）→ 各分段字段卡片。两张受控卡片关闭（show=false）时不在预览中出现。

## 十七、验收要点（开发 checklist）

- [ ] 报告模板列表页：卡片网格展示，支持按报告类型/状态/适用产品筛选
- [ ] 模板基础信息：名称/报告类型/适用产品/描述/状态/默认开关/版本号可配置
- [ ] 报告内容配置：分段可增删/排序（来源类型在新建时由「＋ 数据源/接口/规则集 分段」按钮确定，卡片上仅展示彩色标签、不提供切换）；**展示项在卡片勾选、配置项收进「配置来源」弹窗**（分离避免凌乱）；数据源（库表连接+读取表字段+勾选展示字段）/ 接口（API地址+输入参数表+输出字段表，输出可新增）/ 规则集（选系统内规则合集+勾选规则项用/不用+命中未命中显示）；弹窗底部按来源提供「测试连接 / 测试接口 / 测试规则集」可用性校验
- [ ] 评分展示配置：评分组件类型、等级划分（区间/名称/颜色/说明文案）可配置
- [ ] 结论配置：每等级映射自动审核/人工审核/决策建议/授信额度/可执行操作/复核级别
- [ ] 样式主题：4套预设 + 自定义颜色/间距/字体/表格/圆角/页眉
- [ ] 导出模板：格式/页眉页脚/水印/签名区/内容范围可配置
- [ ] 实时预览：独立子页面（cm:report-template-preview?id=），支持按报告类型的多态样例数据切换、以角色预览、返回详情
- [ ] 模板版本管理：草稿/启用/停用/复制/删除/对比
- [ ] 变更日志：记录每次变更的版本/操作人/时间/摘要
- [ ] 与报告衔接：模板配置修改后，新进入件的报告按新模板渲染
- [ ] 权限控制：5种角色的查看/编辑/启用/删除权限矩阵
