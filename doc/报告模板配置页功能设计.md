# 报告模板配置页 · 功能设计

> 本文档定义「零售信贷风控 — 贷前审核」模块下「报告模板配置页」的产品功能设计。
> 该页面用于配置四大报告（信息核验 / 信用风控 / 欺诈识别 / 决策报告）的展示模板，包括：报告内容（分段/字段显隐）、评分展示方案、不同评分对应的业务流程、样式主题、导出模板。
> 对应代码展示端：`SaaS/src/console/PreVerifyDetail.tsx`、`CreditReportDetail.tsx`、`FraudScheme4Detail.tsx`（决策报告详情页待建）。
> 设计模式参考已落地的「核验规则配置页」（`VerifyRuleEditor.tsx`）：左侧模板列表 + 右侧配置面板。

## 一、页面定位与边界

### 1.1 基础定位

| 维度 | 说明 |
|------|------|
| **所属模块** | 零售信贷风控 — 贷前审核 |
| **页面名称** | 报告模板配置 |
| **页面类型** | 配置型管理页（左侧模板列表 + 右侧配置面板） |
| **访问入口** | 左侧菜单「公共配置」→「报告模板」（或各报告子模块下独立的「报告模板」入口） |
| **操作权限** | 系统管理员、风控主管可编辑；风控专员仅可查看与切换模板 |
| **数据持久化** | 后端模板配置库，支持多模板并存、版本管理与默认模板设置 |

### 1.2 与信用模型配置的关系

| 维度 | 信用模型配置 | 报告模板配置 |
|------|-------------|-------------|
| **关注点** | 评分公式与参数（如何算分） | 报告展示与业务流程（分数如何展示、如何决策） |
| **使用者** | 风控策略岗、系统管理员 | 风控主管、系统管理员 |
| **修改影响** | 影响新进入件的评分计算 | 影响新进入件的报告渲染与业务操作流程 |
| **关系** | 信用模型输出「分数」 | 报告模板接收「分数」→ 展示 + 决策分流 |

> **核心原则**：信用模型配置是「评分引擎」，报告模板配置是「评分结果的展示与业务应用」。二者独立配置、组合生效。

## 二、在贷前审核与贷中监控中的作用

### 2.1 贷前审核中的作用

1. **报告内容按需展示**：不同产品/客群的报告展示内容不同。如信用贷需要展示完整的信用风控六维分析，小额快贷只需要展示简化版评分与决策建议。
2. **评分展示标准化**：统一各报告的评分展示方式（大数字/环形图/进度条）、等级划分、颜色语义，确保信审员快速理解风险等级。
3. **业务流程灵活配置**：不同产品可以配置不同的评分区间 → 决策建议 → 可执行操作的映射。如A产品「60分以上自动通过」，B产品「70分以上才自动通过」。
4. **监管合规适配**：不同监管要求下，报告导出格式、水印、签名区、留痕字段可灵活配置。

### 2.2 贷中监控中的作用

1. **模板迭代优化**：根据贷后表现（逾期率、坏账率、信审员反馈），调整报告中展示的重点字段与风险提示方式。
2. **A/B 测试**：不同客群使用不同报告模板，对比信审效率、误杀率、通过率，找出最优展示方案。
3. **多租户适配**：SaaS 平台服务多个机构客户时，每个客户可配置独立的报告模板（品牌色、Logo、字段显隐、决策阈值）。

## 五、模板基础信息（右侧顶部，所有 Tab 共用）

选中模板后，右侧顶部固定显示基础信息配置区。

| 配置项 | 类型 | 必填 | 默认值 | 说明 |
|--------|------|:----:|--------|------|
| **模板名称** | 文本输入 | 是 | — | 如「标准信息核验报告模板」 |
| **报告类型** | 单选（只读） | 是 | — | `信息核验 / 信用风控 / 欺诈识别 / 决策报告`，新建时选择后不可修改 |
| **适用产品** | 多选下拉 | 否 | 全产品 | 该模板默认应用于哪些产品 |
| **模板描述** | 多行文本 | 否 | — | 说明模板用途与适用场景 |
| **模板状态** | 单选 | 是 | 草稿 | `草稿 / 已启用 / 已停用` |
| **设为默认模板** | 开关 | 否 | 关闭 | 开启后新进入件默认使用该模板 |

## 六、Tab 一：报告内容配置

### 6.1 功能概述

配置报告中「显示哪些分段、每个分段内显示哪些字段、分段的展示顺序」。**核心模型：每个分段有且仅有单一来源（sourceType）**，字段即该来源的具体产出项。来源类型决定分段如何取数，也决定其下每个字段能配置什么：

| 来源类型 | 含义 | 典型例子 | 字段配置项 |
|---------|------|-----------|------------|
| `data_source` 数据源（用户首填） | 来自进件表单 / 用户上传的原始数据 | 基本信息、证件照 | 绑定来源字段、是否脱敏 |
| `api` 接口调用结果 | 调用某引擎/接口得到，必有「输入→输出」 | 异常值模型卡、决策建议、征信查询 | 接口名、输入参数映射、输出字段名、对应输入 |
| `rule_set` 规则集碰撞结果 | 规则集命中/未命中的碰撞结论 | 多源并行核验、各欺诈详情、黑名单 | 规则集名、规则项、命中显示、未命中显示 |

> 设计要点：**字段不是内置写死的**，而是在本 Tab 前端「配出来」的——可新增分段、新增/删除/重排字段、改分段的来源类型，并逐项设置来源。内置 `SECTION_CATALOG` 仅作为新建模板时的**初始种子内容**，全部可改可删。

### 6.2 交互方式

- **分段列表**：以卡片/行列出该报告类型下的所有分段，每段带来源类型彩色标签（数据源=绿 / 接口=蓝 / 规则集=紫）。
- **新增分段**：面板顶部按来源类型三个按钮「＋ 数据源分段 / ＋ 接口分段 / ＋ 规则集分段」，新建空白分段（含 1 个新字段）。
- **删除分段**：每段「删除分段」按钮（确认后连其下字段一并删除）。
- **上移/下移**：每段及每段内字段均有 ↑/↓ 调整顺序。
- **改来源类型**：每段右侧下拉「数据源 / 接口调用 / 规则集」；切换时该段下字段的来源配置项按新类型重置为默认值（保留字段名/说明/显隐）。
- **显示/隐藏开关**：分段与字段各有一个 Checkbox；取消勾选后该分段/字段在报告与预览中不渲染。至少保留 1 个分段（仅剩 1 个时置灰）。
- **来源级配置**：
  - `api` 段：可填「接口名」，并在「输入参数」区增删多行 `参数 key ← 数据来自`（体现接口调用的输入→输出）。
  - `data_source` / `rule_set` 段：填「数据源名 / 规则集名」。
- **字段级配置**（按段落来源类型显示不同项）：
  - `data_source`：下拉「来源字段」（来自 `DATA_SOURCE_FIELD_POOL` 池）+ 「脱敏显示」勾选。
  - `api`：填「输出字段名」+ 下拉「对应输入」（来自本段输入参数 key）。
  - `rule_set`：下拉「规则项」（来自 `RULE_POOL` 池）+ 填「命中显示」「未命中显示」。

### 6.3 四大报告的分段与字段清单（初始种子；均可在前端增删改）

#### ① 信息核验报告（7 个分段）

> 来源类型：`score_model`·`conclusion_process`·`op_logs` = 接口调用结果；`basic_info`·`id_images` = 数据源（用户首填/上传）；`single_verify`·`cross_fusion` = 规则集碰撞结果。

| 序号 | 分段标识 | 分段名称 | 可配置字段 |
|:----:|---------|---------|-----------|
| 1 | `score_model` | 异常值模型卡 | 异常值大数字、满分分母、风险档标签、阈值刻度条、构成项分解表、合计行、判定规则文本、审计栏、查看打分权重明细按钮 |
| 2 | `conclusion_process` | 结论与终审操作卡 + 核验过程 | **结论卡**：系统结果、人工审核、操作人员、授信建议、建议理由、正向因素、风险因素、参考授信额度、操作按钮组；**核验过程**：核验过程时间线、步骤图标、步骤状态色、步骤耗时 |
| 3 | `basic_info` | 用户基本信息 | **基础字段**：姓名、身份证号、手机号、银行卡号、开户行、年龄、学历、工作单位、月收入、居住地址、婚姻；**环境采集**：设备指纹、IP地址、GPS定位、进件渠道、APP版本 |
| 4 | `id_images` | 用户证件照 | 身份证人像面、身份证国徽面、活体人脸（视频）、银行卡、OCR识别文本 |
| 5 | `single_verify` | 多源并行核验单项报告 | **5数据源卡片**（可独立隐藏）：公安实名、银行卡四要素、运营商实名、终端设备、联防联控；**单卡内部**：卡片头部、整体结论、结论原因、子字段列表、核验流水号、核验时间、调用渠道、调用耗时 |
| 6 | `cross_fusion` | 数据交叉融合综合报告 | 综合风险头部栏、5项原子结论卡、多源风险交叉疑点明细、异常值构成项分解、风险标签、判定规则文本、审计信息、查看打分权重明细弹窗入口 |
| 7 | `op_logs` | 单项核验全量操作日志 | 单项操作记录、报告级操作记录、操作日志时间线、附件列、复核状态列 |

#### ② 信用风控报告（8 个分段）

> 来源类型：`credit_score_overview`·`credit_conclusion`·`risk_factors`·`score_trend`·`risk_radar`·`credit_suggestion`·`credit_logs` = 接口调用结果；`applicant_info`·`history_records` = 数据源（用户首填/历史征信）。

| 序号 | 分段标识 | 分段名称 | 可配置字段 |
|:----:|---------|---------|-----------|
| 1 | `credit_score_overview` | 信用评分总览 | 环形评分图、信用等级（A/B/C/D）、六维评分条、风险标签、导出报告按钮 |
| 2 | `credit_conclusion` | 结论与终审操作卡 | 系统结果、人工审核、操作人员、授信建议、建议理由、正向因素、风险因素、参考授信额度、操作按钮组 |
| 3 | `applicant_info` | 用户基本信息 | 同信息核验「用户基本信息」 |
| 4 | `risk_factors` | 风险因子分析 | 6维评分卡片（身份/还款/信用历史/行为/设备/关联）、维度说明表（权重/逻辑/来源） |
| 5 | `score_trend` | 信用评分趋势 | SVG折线图（用户vs行业 近7月）、趋势分析文案 |
| 6 | `risk_radar` | 风险维度雷达图 | SVG雷达图（当前vs行业平均）、雷达图分析文案 |
| 7 | `credit_suggestion` | 风控决策建议 | 系统建议文案、正向因素列表、风险因素列表、4决策按钮（审核通过/拒绝授信/提交人工复核/退回补充材料） |
| 8 | `history_records` | 历史授信记录 | 历史授信记录表（授信时间/额度/期限/状态/逾期情况） |
| 9 | `credit_logs` | 风控操作日志 | 时间线日志（操作人/操作/时间/结果/备注） |

#### ③ 欺诈识别报告（10 个分段）

> 来源类型：`fraud_score_model`·`disposal_bar`·`fraud_logs` = 接口调用结果；`basic_info` = 数据源（用户首填）；`identity_fraud`·`info_forgery`·`device_fraud`·`behavior_fraud`·`gang_fraud`·`blacklist_hit`·`history_fraud` = 规则集碰撞结果。

## 八、Tab 三：业务流程配置

### 8.1 功能概述

配置不同评分等级对应的：自动审核决策、人工审核初始状态、可执行操作、决策建议文案、授信额度比例。这是报告模板配置的核心业务配置，直接决定进件的风控流程。

> **与「评分方案」的联动（重构要点）**：业务流程行与评分方案中的等级按 **index 显式对齐**（由 `syncFlowToGrades()` 保证），不再依赖等级名称字符串匹配。
> - **第 0 行固定为「计算中」**：评分尚未得出的初始态，自动审核=处理中、人工状态=核验计算中、仅可查看，该行**不可配置**（gradeId 固定为 `—`）。
> - 其后每一行一一对应「评分方案」里的第 i 个等级；在评分方案里**改名 / 新增 / 删除等级**，业务流程会**自动同步跟随**（已配置项尽量保留）。
> - 因此业务流程里**无需再单独命名等级**，等级名称/数量完全由评分方案驱动。

### 8.2 业务流程配置表

以表格形式展示「评分等级 → 业务流程」的映射关系，首行为固定「计算中」态，其后每行对应评分方案中的一个等级。

| 配置项 | 类型 | 说明 |
|--------|------|------|
| **评分等级** | 只读 | 取自「评分方案」中的等级，第 0 行固定显示「计算中」（不可配置，不对应任何等级） |
| **自动审核决策** | 单选 | `通过 / 预警 / 拒绝 / 处理中` |
| **人工审核初始状态** | 单选 | `— / 待确认 / 待审核 / 核验计算中` |
| **决策建议文案** | 文本 | 该等级在报告中显示的决策建议，如「信用良好，建议正常授信」 |
| **授信额度比例** | 数字 | 该等级可获得的授信额度占申请额度的百分比（0%–100%） |
| **可执行操作** | 多选 | 该等级下审核员可执行的操作（见 8.3） |
| **是否需要人工复核** | 开关 | 开启后，该等级的进件必须经人工审核才能办结 |

## 十一、实时预览（独立子页面）机制

### 11.1 预览入口与独立子页面

- 实时预览**不再内嵌在详情页**，改为点击详情页顶栏 [预览] 按钮（列表卡片的「预览」操作亦同）跳转到独立子页面 `cr:report-template-preview?id={模板ID}`。
- 子页面为**独立路由、全屏渲染**，与详情页是「详情 → 预览」的二级跳转关系；顶部 `DetailHeader` 提供「← 返回详情配置」一键回到原模板（携带 `?id=` 参数定位到对应模板详情）。
- 子页面**只读展示**，不保存任何配置；编辑配置需回到详情页。

### 11.2 预览数据

- 预览使用**真实样例数据**（定义在 `reportTemplateData.ts` 的 `PREVIEW_SAMPLE`：按报告类型内置各分段/字段的真实样例值），渲染出报告**真实长相**（评分卡 + 阈值刻度条 + 各分段字段），而非占位框。
- 状态切换选项来自同文件的 `PREVIEW_STATES`，按报告类型提供：
  - 信息核验：`安全 / 关注 / 警示 / 高危`（对应异常值 12 / 40 / 65 / 90，**越高越危险**）
  - 信用风控：`A级 / B级 / C级 / D级`
  - 欺诈识别：`极低 / 低 / 中 / 高 / 极高`
  - 决策报告：`优先通过 / 通过 / 限制额度 / 严格限制 / 拒绝`
- 子页面顶部另提供「**以角色预览**」下拉（系统管理员 / 风控主管 / 风控策略岗 / 风控专员 / 数据分析师）：仅改变本页**可编辑态的呈现**（如风控专员下编辑控件置灰），用于让配置者感知权限差异，**不影响模板真实配置权限**。

### 11.3 预览渲染策略

- 子页面读取 `PREVIEW_SAMPLE` 真实样例数据，进入即渲染，与真实报告详情页 **1:1 还原**，使用同一套 `Panel` 组件。
- 子页面不支持交互（按钮点击、弹窗展开等仅作展示，不触发实际逻辑）。
- （历史方案中的"300ms debounce 实时联动"已废弃，改为子页面进入时一次性渲染。）

## 十二、模板版本管理与变更日志

### 12.1 版本管理

| 操作 | 说明 |
|------|------|
| **保存草稿** | 编辑后保存为草稿状态，不影响生产环境 |
| **启用** | 将草稿/停用模板启用，启用后新进入件按新模板渲染 |
| **停用** | 将已启用模板停用，停用后新进入件使用默认模板 |
| **设为默认** | 将该模板设为该报告类型的默认模板 |
| **复制模板** | 基于当前模板创建副本，副本名称为「{原名称} - 复制」 |
| **删除** | 删除草稿/停用状态的模板；已启用模板需先停用才可删除 |
| **对比** | 选择两个版本，系统高亮展示差异项 |

### 12.2 变更日志

| 字段 | 说明 |
|------|------|
| **版本号** | 模板版本，格式 `V{major}.{minor}` |
| **操作类型** | `创建 / 编辑 / 启用 / 停用 / 复制 / 删除` |
| **操作人** | 系统用户 |
| **操作时间** | 精确到秒 |
| **变更摘要** | 自动提取变更内容（如「隐藏了字段：GPS 定位」「调整了分段顺序」「修改了业务流程：中风险授信额度 70%→60%」） |

## 十四、与报告详情页的衔接

| 配置项 | 影响报告详情页的表现 |
|--------|---------------------|
| **分段顺序** | 报告详情页中 Panel 的渲染顺序 |
| **分段显示/隐藏** | 对应 Panel 是否渲染（`condition && <Panel>`） |
| **字段显示/隐藏** | Panel 内部各字段/表格列的渲染控制 |
| **评分展示配置** | 评分组件类型、等级名称、颜色、阈值刻度条、构成项分解 |
| **业务流程配置** | 报告中显示的决策建议文案、操作按钮的可用性、授信额度比例 |
| **样式主题** | CSS 变量 / Tailwind 配置切换（主色调、风险色、字体、间距、圆角） |
| **导出模板** | 导出按钮的可用格式、导出文件的样式与内容范围 |
| **锚点导航** | 右侧 `navCards` 的顺序与可见性同步跟随分段配置 |

> 模板配置生效后，**新进入件**生成的报告按新模板渲染；**历史已生成报告**为快照，不受模板变更影响。

## 十五、数据模型（TypeScript 类型）

```typescript
// 报告模板整体结构
interface ReportTemplate {
  id: string
  name: string                    // 模板名称
  reportType: ReportType          // 报告类型
  scope: string[]                 // 适用产品
  status: '草稿' | '已启用' | '已停用'
  isDefault: boolean              // 是否为默认模板
  description: string             // 模板描述
  version: string                 // 版本号
  lastEditor: string
  lastEditTime: string

  // Tab 一：报告内容配置
  sections: SectionConfig[]       // 分段配置

  // Tab 二：评分展示配置
  scoreDisplay: ScoreDisplayConfig

  // Tab 三：业务流程配置
  businessFlow: BusinessFlowConfig[]

  // Tab 四：样式主题
  theme: ThemeConfig

  // Tab 五：导出模板
  export: ExportConfig

  // 变更日志
  changeLogs: TemplateChangeLog[]
}

type ReportType = 'info_verify' | 'credit' | 'fraud' | 'decision'

// 分段配置
interface SectionConfig {
  id: string           // 分段标识
  name: string         // 分段名称
  desc: string         // 分段业务说明（勾掉会怎样）
  order: number        // 排序序号
  visible: boolean     // 是否显示
  fields: FieldConfig[] // 字段配置
}

// 字段配置
interface FieldConfig {
  id: string        // 字段标识
  name: string      // 字段名称
  desc: string      // 字段业务说明（配置者看得懂在配什么）
  visible: boolean  // 是否显示
}

// 评分展示配置
interface ScoreDisplayConfig {
  displayComponent: '大数字' | '环形图' | '进度条' | '仪表盘'
  showDescription: boolean
  showThresholdBar: boolean
  showComponents: boolean
  showRiskTags: boolean
  grades: ScoreGrade[]
}

// 评分等级
interface ScoreGrade {
  grade: string        // 等级标识，如 'A' / '低'
  label: string        // 等级名称，如 '优秀' / '低风险'
  minScore: number     // 评分下限（含）
  maxScore: number     // 评分上限（含）
  riskLevel: '低' | '中' | '高' | '极高'
  color: string        // 颜色
  description: string  // 等级说明文案
}

// 业务流程配置（首行固定为「计算中」态，其后每行对应评分方案中的一个等级）
interface BusinessFlowConfig {
  gradeId: string              // 关联的评分等级标识
  autoDecision: '通过' | '预警' | '拒绝' | '处理中'
  manualStatus: '—' | '待确认' | '待审核' | '核验计算中'
  suggestionText: string        // 决策建议文案
  creditLimitRatio: number     // 授信额度比例（%）
  needManualReview: boolean     // 是否需要人工复核
  reviewLevel: '单人复核' | '双人复核' | '初审+终审两级'
  allowedActions: string[]      // 可执行操作标识列表
}

// 样式主题
interface ThemeConfig {
  preset: '标准蓝' | '专业灰' | '政务红' | '极简白'
  primaryColor: string
  passColor: string
  warningColor: string
  rejectColor: string
  spacing: '紧凑' | '标准' | '宽松'
  fontSize: '小' | '标准' | '大'
  tableStyle: '线框表' | '斑马纹' | '无边框'
  borderRadius: '直角' | '小圆角' | '大圆角'
  headerStyle: '简洁' | '标准' | '完整'
}

// 导出模板
interface ExportConfig {
  formats: ('PDF' | 'Word' | 'Excel')[]
  defaultFormat: string
  pdfHeader: string
  pdfFooter: string
  watermark: { enabled: boolean; text: string; opacity: number }
  wordStyle: '与页面一致' | '独立样式'
  excelSplitSheet: boolean
  exportScope: '完整报告' | '仅当前可见分段' | '自定义范围'
  includeOpLogs: boolean
  includeSignature: boolean
  signatureTemplate?: string
}

// 变更日志
interface TemplateChangeLog {
  version: string
  action: '创建' | '编辑' | '启用' | '停用' | '复制' | '删除'
  operator: string
  timestamp: string
  summary: string
}
```
